## サーバー設定の条件

IP制限は `REMOTE_ADDR` に依存します。PHP 7.4用のWordPress公式Dockerイメージでは、Apacheがループバック接続からの `X-Forwarded-For` を信頼する設定だったため、偽装テストでIP制限の期待値と一致しませんでした。プロキシを使わない隔離テスト環境だけで `remoteip` 設定を無効にして再検証し、成功しました。通常開発環境のApache設定は変更していません。

本番でプロキシを使う場合は、信頼する中継元を実際のプロキシに限定してください。Webサーバーが偽のIPを採用した後では、PHP側だけで元の接続元を復元できません。メール単位の制限はIP設定と独立しています。

HTTPS、掲載ページとadmin-postのキャッシュ除外、WP-Cronの定期実行が必要です。メールと番号を知っている人が取得できる仕様で、メール所有確認は行いません。

## 再実行

通常開発環境での統合・追加監査：

```powershell
docker compose -f docker/compose.yml cp tests/documents-integration.php web:/tmp/sosc-documents-integration.php
docker compose -f docker/compose.yml cp tests/documents-audit.php web:/tmp/documents-audit.php
docker compose -f docker/compose.yml exec -T -e SOSC_DOCUMENT_AUDIT=1 web php /tmp/sosc-documents-integration.php
```

`SOSC_DOCUMENT_ARTIFACTS=1` を追加すると、ダミー注文の比較用PDFをコンテナの `/tmp/sosc-document-audit` に出力します。Gitや公開ディレクトリには保存しません。

PHP 7.4は `docker/compose.compat.yml` の別プロジェクト `sosc-doc-audit74` で新規DB・WordPressを構築し、Welcartと対象プラグインを有効化して実施しました。ローカル専用URLを `http://localhost` とし、`SOSC_DOCUMENT_TEST_BASE=http://localhost` を指定しました。税表示を有効にした隔離環境で同じテストを実行しています。

障害注入ファイル `tests/documents-fault-fixture.php` は、使い捨ての隔離環境のmu-pluginsだけへ配置し、`SOSC_DOCUMENT_FAULT_TESTS=1` を指定します。共有開発環境・本番には配置しないでください。
