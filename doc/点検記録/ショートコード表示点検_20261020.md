# ショートコード表示点検

- 点検日: 2026-10-20
- 対象: `so-short-code` の公開画面ショートコード15種、スコープ版Bootstrap、帳票フォーム、管理画面のショートコード・Welcart・その他の3タブ。
- 環境: ローカルDockerのWordPress・Welcart、Chrome Headlessの実ブラウザ描画。検証用投稿・商品・SKU・分類・ページは `tests/visual-fixture.php` で作成し、点検後に削除。
- 既存差分: 帳票フォームとタグ表示のラッパー修正などが未コミット。今回、製品コードの追加修正はない。

## 実画面の結果

| 画面 | 配置したショートコード | 確認結果 |
| --- | --- | --- |
| 情報一覧 | `sosc_info_list01`〜`05` | サンプル投稿と分類を使い、320・390・1280pxで描画。カード画像、表、日付、スマートフォン用の縦並びを目視確認。横スクロールなし。 |
| カード等 | `sosc_blog_card01`、`sosc_tag_view01`、`sosc_target_content` | サンプル投稿・タグ・参照先を表示。320・390・1280pxで横スクロールなし。 |
| Welcart | `sosc_wc_item_list01`〜`03`、`sosc_wc_item_card01`〜`03`、`sosc_wc_documents` | サンプル商品とSKUを使い、一覧・カード・価格・帳票フォームを実表示。320・390・1280pxで横スクロールなし。帳票フォームの入力欄と2ボタンも収まる。 |

上記3画面は、fixture修正後にDevToolsで320・390・1280pxを再計測した。`documentElement.scrollWidth` は320px・390pxで各画面320px・390px、1280pxでは情報一覧とカード画面が1280px、Welcart画面が1265pxだった。修正前のfixtureでも360・768・1024pxを計測し、横スクロールは発生しなかったが、二重表示があるため表示品質の最終根拠には用いない。画像なし時はプラグインの `NO IMAGE` 代替画像が表示された。

スコープ版Bootstrapは `actions.php` で読み込まれ、公開側の各ショートコードと帳票フォームに `.sosc-bs-scope` がある。帳票フォームのBootstrapクラスはラッパーの子に配置されている。タグ表示の `row w-100` もスコープの子にある。管理画面も認証済みChromeで320・390・1280pxを表示し、ショートコード・Welcart・その他の3タブにページ全体の横はみ出しがないことを確認した。実画像を添付した場合、長い商品名・翻訳文、Safari・Firefoxは未確認とする。

追加点検では、固定日付の検証ページで公開画面72枚・管理画面9枚の[正規デザインキャプチャ](../../tests/visual-baseline/README.md)を作成した。初版はテーマの固定ボタンの遷移状態を含み、比較時に繰り返し差分が出た。試作版を経て、遅延画像の読込後にページ先頭へ戻し、2秒待機し、撮影中だけテーマの `#pagetop` を非表示にした現行基準を別版で作成した。[比較スクリプト](../../tests/visual/capture.cjs)で公開画面72枚を2回、[管理画面比較スクリプト](../../tests/visual/admin-capture.cjs)で管理画面9枚を1回独立再撮影し、合計81枚が基準と一致、ソースhash差分も0件だった。WordPress 7.1.3、SWELL 2.15.0、so-short-code 3.8.5、Welcart 2.12.5かつactiveで、基準の環境条件と一致した。将来のデザイン変更後は[デザイン回帰Skill](../../.agents/skills/wp-plugin-visual-regression/SKILL.md)で比較する。

月次バックアップタブも390・1280pxで実表示し、ページ全体の横はみ出しはなかった。保存先の識別子が表示されるため、撮影した一時画像は削除し、Git管理する基準画像には含めていない。箱詰めの注文画面は注文情報を扱う別機能で、今回の固定サンプル基準の対象外とする。

fixtureの削除後、同じfixtureの `status` で `posts=0 terms=0 skus=0` を確認した。一時的なmu-pluginの計測プローブも削除した。
