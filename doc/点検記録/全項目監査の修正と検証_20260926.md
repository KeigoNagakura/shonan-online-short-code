### 再監査で見つかったSQL復元の問題

| ID | 問題 | 対応 |
| --- | --- | --- |
| F18 | 数値を一律に16進リテラルで保存すると、復元時の型変換で値が変わる（INTの1が49、7が55になることを再現） | 列型に応じて数値・バイナリ・文字列を出力。数値はPHPの整数・浮動小数へ変換せず精度を維持し、JSON・ENUM等には接続文字コードを明示 |
| F19 | 生成列にもINSERT値を指定し、復元が失敗する | 生成列は取得時の並び順に利用できる状態を保ち、INSERT対象から除外してDBで再計算 |
| F20 | SELECT *に含まれない非表示列の値がバックアップから欠落する | 列定義から明示的なSELECT対象を作成して非表示列も保存 |
| F21 | バッククォートを含む主キー名を誤って復元し、501件目以降の読み取りが失敗する | SQL用にエスケープした列名と元の列名を分離し、取得結果の参照には元の名前を使用 |

`tests/backup-storage-regression.php`は専用の一時テーブルだけを作成・ダンプ・再投入・削除し、505行の全値が一致することを確認する。対象は整数、最大符号なしBIGINT、小数、浮動小数、BIT、バイナリ、ENUM、SET、日本語JSON、日付・時刻・年、NULL、生成列、非表示列、特殊文字を含む主キー。既存の投稿・注文テーブルへSQLを再投入するテストではない。

**F18〜F20の修正は新しく作成するプラグインのバックアップに適用される。修正前のZIPは復元用としてそのまま使わず、修正適用後に再作成すること。既存ZIPのSQLは自動修復されない。Dockerの別スクリプトによるmysqldumpは、このDatabaseDumperの不具合の対象外。**

### マージ後の追加指摘への対応

- F22：空間型のダンプは成功するが復元で失敗する問題を修正。`ST_AsWKB`・`ST_SRID`・`ST_GeomFromWKB`で空間データを復元し、文字コード変換による破損を回避する。既存の505行復元テストに空間8型とSRID 4326を追加。修正前の復元失敗、修正後の全値一致を確認する。
- F23：技術仕様書に残っていた「復号不能時は暗号化なし」「暗号化方式設定を判定に使用しない」を、実装のエラー停止・暗号化必須状態の判定へ訂正。
- F24：PRスキルの必須バージョン更新を撤回し、通常PRでは据え置き、リリース準備または明示的な更新依頼時に関連項目を同期する方針へ統一。

### PR #17マージ後の再監査への対応

- F25：ENUM/SET主キーではキセットページングを使わず、一貫したスナップショット内で主キー順のOFFSETページングを行うよう修正。定義順と文字列順が異なるENUM主キー505行の全件復元を回帰テストへ追加。
- F26：ルーチンとトリガーの作成時SQLモードをダンプへ保存し、復元時だけ適用して元のセッション設定へ戻すよう修正。`PIPES_AS_CONCAT`を使うプロシージャの結果を比較する回帰テストを追加。
- F27：イベントの作成時タイムゾーンをSQLモードとともに保存し、復元後の絶対実行時刻が変わらないよう修正。`+09:00`で作成したイベントのタイムゾーンと壁時計時刻を比較する回帰テストを追加。
- F28：`DEFINER`除去をCREATE文の構造上の指定だけに限定し、ルーチン本文中の同名文字列を保持するよう修正。
- F29：箱詰め送料キャッシュの識別値へ、受け取った基本送料、送料無料状態、顧客情報へフォールバックした配送先、設定リビジョンを追加。条件変更時に必ず再計算する回帰テストを追加。
- F30：空カートなど箱詰め対象外の結果と例外時に、直前の静的計算結果を消去するよう修正。対象外判定を繰り返しても過去の送料が復活しない回帰テストを追加。
- F31：復元SQLが接続元のSQLモード、外部キー検査、文字コード、照合順序を固定値のまま残す問題を修正。開始時のセッション値を保存し、正常終了時にすべて復旧する回帰テストを追加。

追加修正後、MySQL 8.4.11で空間8型を含む505行の復元一致を確認。MySQL 8.0を使うWordPress 6.0.3／PHP 7.4.33とWordPress 7.0.3／PHP 8.3.33の回帰マトリクスも合格。PHP 7.4／8.3構文検査、変更PHPのWPCS、スキルのquick_validate、配布ZIPのSHA-256再検証に合格した。表示資産は変更しておらず、今回ブラウザ表示テストは再実行していない。MySQL 5.7・MariaDBでの空間型復元は未確認。
