# Git連動プラグイン自動更新

作成日: 2026-11-10 ／ 第2版 ／ 最終更新日: 2026-11-10

## 更新の流れ

公開リポジトリ `KeigoNagakura/shonan-online-short-code` のPRを `main` にマージすると、GitHub ActionsがPHP構文とComposer依存を確認し、ZIP内のプラグイン版を一つ進め、GitHub ReleaseにZIPを公開する。WordPressはGitHubの最新リリースAPIから版、ZIP URL、SHA-256を取得し、このプラグインだけをバックグラウンド更新する。ZIPはダウンロード後にSHA-256を照合する。

ワークフローは [plugin-update-release.yml](../../.github/workflows/plugin-update-release.yml)、ZIP生成は [build_github_release.py](../../scripts/build_github_release.py)、更新判定は [update.php](../../src/so-short-code/update/update.php) にある。GitHub Actionsの `contents: write` 権限を使う。SSH配布用の秘密情報は不要。

## 初回移行

現行の3.8.5以前は旧更新サーバー `api.shonan-online.com` を参照する。GitHub Releaseへの切替を含む最初のZIPは、対象サイトで一度手動適用する必要がある。最初のZIPが公開された後、サイトのバックアップと動作を確認してから適用する。以降はWordPressの定期更新処理で自動適用される。マージ直後の即時適用は保証しない。

WordPress側で `AUTOMATIC_UPDATER_DISABLED` 等の自動更新停止設定やCron停止がある場合は、自動適用されない。適用対象は `so-short-code/so_short_code.php` のみ。他のプラグインの設定は変更しない。

## 運用と復旧

- PRをマージする前に、変更内容と対象サイトへの影響を確認する。マージ後のRelease公開は自動で進む。
- GitHub Actionsが失敗した場合は、失敗したステップを確認して修正する。同じコミットのReleaseが既にある場合、再実行で二重公開しない。
- ZIP公開後に問題が見つかった場合は、修正PRをマージして次版を公開する。既存タグやRelease assetを上書きしない。
- GitHub APIまたはZIP取得が失敗した場合は更新を保留する。既存プラグインはそのまま動作する。

版番号は最新Releaseとソース版の大きい方のパッチ番号に1を加える。配布ZIP内のヘッダーと `SOSC_VERSION` は同じ版になる。ソース側の版は次の手動リリース基準値として残る。Releaseのタグは実際の配布ZIP版を表す。

## 確認項目

1. Actionsの `Plugin update release` が成功し、Releaseに `so-short-code-XX.XX.XX.zip` が一つある。
2. ZIPのルートが `so-short-code/` で、ヘッダーと `SOSC_VERSION` がReleaseタグと一致する。
3. 代表サイトで更新通知、SHA-256検証、適用後の有効化と主要機能を確認する。初回移行では手動適用する。
