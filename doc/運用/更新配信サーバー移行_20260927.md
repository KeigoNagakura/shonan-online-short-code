# 更新配信サーバー移行仕様

> 文書整理日: 2026-09-27。既存本文を保持し、日本語名・分類・参照リンクを整理。ファイル名の日付は本文の作成・実施日を優先し、不明なものは整理日とした。 以下は移設前からの運用方針・計画。旧docker/・CI資材や外部設定の適用状態は未確認。現在の起動は[Docker開発環境](Docker開発環境_20260927.md)を参照。

> 第2版。最終更新日: 2026-11-10。現行更新処理の同一ホスト制約に合わせて旧ホストの維持条件を修正。

## 1. 目的

WordPressプラグインの更新配信先を、次回リリースから以下のように移行します。

```text
旧: https://api.shonan-online.com/
新: https://sosys.shonan-online.com/
```

既存バージョンは旧ホストの更新JSONしか参照できないため、コードのURLだけを変更して旧ホストを停止してはいけません。

## 2. 対象ファイル

```text
/out_source/so-short-code.json
/out_source/so-short-code-XX.XX.XX.zip
```

例：

```text
https://sosys.shonan-online.com/out_source/so-short-code.json
https://sosys.shonan-online.com/out_source/so-short-code-03.07.00.zip
```

## 3. 移行スケジュール

### 次回リリースまで

- 現在の `api.shonan-online.com` を使用します。
- コードと更新JSONの配信先URLはまだ変更しません。
- `sosys.shonan-online.com/out_source/` を準備します。

### 次回リリース

- `settings.php` の `SOSC_API_URL` を新ホストへ変更します。
- 更新JSONの `download_url` を新ホストへ変更します。
- 新ホストへ更新JSONと配布ZIPを配置します。
- 旧ホストにも、新しいバージョンを通知する更新JSONを配置します。
- 旧ホストの更新JSONは旧ホスト上のZIPを指定します。現行の更新処理はJSON取得元とZIPのホスト一致を検証するため、同じZIPを両ホストへ配置します。

この期間は、旧ホストと新ホストの両方から更新情報を取得できる状態にします。

### 旧ホストを参照するプラグインが残る間

- 旧ホストの更新JSONを維持します。
- 旧バージョンから最新バージョンへ更新できることを定期的に確認します。
- 旧ホストの更新JSONが指す配布ZIPも旧ホストに保持します。

### 旧ホスト廃止の判断

- 既存バージョンの更新処理はJSON取得元とZIPのホスト一致を要求します。旧ホストから新ホストへJSONをリダイレクトするだけでは、旧版の更新が通ると判断できません。
- 旧ホストの廃止は、旧版の利用状況と実機更新試験を確認した別の判断として扱います。それまでは旧ホストのJSONとZIPを継続配信します。

## 4. 旧ホストの配信

旧版向けの `api.shonan-online.com/out_source/` でも、同じバージョンのZIPと旧ホストURLを指すJSONを配ります。新ホスト用とはZIPの中身とSHA-256を一致させ、JSONの `download_url` のホストだけを分けます。手順は[Git連動プラグイン更新配布](Git連動プラグイン更新配布_20261110.md)を参照してください。

## 5. 次回リリースで変更する箇所

### `src/so-short-code/settings.php`

```php
define('SOSC_API_URL', 'https://sosys.shonan-online.com/');
```

### `src/so-short-code/update/so-short-code.json`

```json
{
  "download_url": "https://sosys.shonan-online.com/out_source/so-short-code-XX.XX.XX.zip"
}
```

`XX.XX.XX` は、例えばバージョン `3.7.0` なら `03.07.00` とします。

## 6. 配置前チェック

- `sosys.shonan-online.com` のDNSが正しい
- HTTPS証明書が有効
- 外部からHTTPSでアクセスできる
- `/out_source/` のアクセス権が正しい
- 更新JSONがHTTP 200を返す
- 更新JSONのContent-TypeがJSONとして適切
- 配布ZIPがHTTP 200を返す
- 配布ZIPのContent-TypeがZIPとして適切
- ZIPを展開すると `so-short-code` ディレクトリになる
- JSONの `version` とプラグイン本体のバージョンが一致する
- JSONの `download_url` が実在するZIPを指す

## 7. 更新テスト

最低限、以下の経路を確認します。

1. 旧バージョンをWordPressへインストール
2. 旧 `api.shonan-online.com` の更新JSONへアクセス
3. WordPress管理画面に新バージョンの通知が出る
4. 更新操作で旧ホストのZIPを取得できる
5. 更新後にプラグインを有効化できる
6. 主要ショートコードが動作する

旧ホストの継続配信を確認します。

```powershell
curl.exe -I https://api.shonan-online.com/out_source/so-short-code.json
```

期待結果：

```text
HTTP 200
```

## 8. ロールバック

新ホストで問題が発生した場合：

1. 旧ホストの更新JSONを直前の正常版へ戻す
2. 更新JSONの `download_url` を取得可能な旧ZIPへ戻す
3. コード側URL変更を修正版リリースで戻す
4. 原因と影響バージョンを記録する

公開済みのタグや同名ZIPを差し替えず、修正版は新しいパッチバージョンとして公開します。
