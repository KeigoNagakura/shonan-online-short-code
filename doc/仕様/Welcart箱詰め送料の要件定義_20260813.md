## 2. 背景と目的

Welcart標準の送料計算を補完し、カート内の商品を登録済みの外箱へ仮想的に箱詰めした結果に基づいて送料を計算する。

管理者は複数種類の外箱を登録し、各外箱へWelcartの「配送方法＋送料」を関連付ける。商品には直方体としての寸法と配置制約を設定する。注文時は、商品寸法、購入者が選択した配送方法、クール区分、外箱の有効状態、および配送先向け送料から使用可能な外箱を自動抽出し、使用箱ごとの送料を合算してWelcartの送料へ適用する。

Welcart本体へカラム、PHP、JavaScript、CSSなどの変更を加えず、Welcart更新時の影響を最小化する。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 箱詰め送料 | 本機能が箱詰め結果から算出する送料 |
| Welcart標準送料 | 本機能を介さずWelcartが算出した送料 |
| 外箱 | 管理者が登録する梱包用の箱 |
| 商品共通設定 | Welcart商品の全SKUへ適用する基本の箱詰め設定 |
| SKU設定 | SKU単位で保持する寸法、重量、梱包マージン設定 |
| 梱包マージン | 商品の実寸に加えて箱詰め計算で確保するSKU単位の余白 |
| 個別対応配送 | 重量超過や箱詰め計算上限超過時に通常の自動箱詰めから外し、管理者が注文確定後に発送方法を個別判断するための共通配送方法 |
| 定形外 | 重量上限超過によって個別対応配送へ切り替えた理由を示す区分 |

## 4. 対象範囲

### 4.1 対象

- 既存プラグイン内での機能有効・無効設定
- 外箱の登録、編集、複製、使用停止、削除
- 外箱とWelcartの「配送方法＋送料」の関連付け
- 商品共通の配置制約とクール便必須設定
- SKU単位の寸法、重量、梱包マージン設定
- 配送要否および送料個別課金設定に基づく箱詰め対象・対象外判定
- 重量上限超過時および計算上限超過時の個別対応配送
- クール便商品の同梱制御
- 送料個別課金商品の別箱計算
- 設定不備、送料なし、同時購入数超過時の購入制御
- カート内容の単一箱・複数箱への箱詰め
- 箱ごとの送料の合算
- Welcart確認画面での複数箱案内
- 受注情報に紐づく箱詰め結果の保存と管理者向け表示
- 管理者手動受注、決済直前ログからの復旧受注、および自動生成受注の箱詰め状態表示
- 個別対応配送の未対応・対応中・対応済み管理
- 管理画面での参考計算
- SKU設定の検証付きCSVエクスポート・インポート
- 設定不足、箱詰め不能、個別対応配送、購入停止の管理者向け警告とログ

### 4.2 初期版の対象外

- 商品間の同梱禁止
- 外箱の在庫数制限
- 温度帯を判定する独自機能
- Welcart本体のテーブル、ファイル、JavaScript、CSSの変更
- JavaScriptだけで完結する送料計算
- 購入者向けの箱ごとの商品内訳表示
- 確定済み受注の箱詰め結果の手動編集

通常商品とクール便商品の区分には、本機能の商品単位の「クール便必須」設定とWelcartの配送設定を利用する。「冷蔵」「冷凍」の細分化は本機能では行わず、クール便対象の有無だけを判定する。クール便商品が1点でも含まれる注文は、常温商品を含む全商品をクール便用の外箱へ箱詰めする。

## 5. 前提と互換性

- 対象WordPressは、既存プラグインの宣言を維持し、最低WordPress 6.0とする。
- 対象PHPは8.2以上とする。2026年11月11日に最低要件を変更した。本文後半に残るPHP 7.4の検証値・ライブラリ選定理由は当時の記録であり、現在の最低要件ではない。
- 最新の開発対象はWordPress 7.0.3、PHP 8.3.33とする。
- 開発環境でWelcart e-Commerce 2.11.34のフックを確認済みとする。
- 初期実装はWelcart 2.11.34で正式検証する。
- さくらのレンタルサーバ スタンダードで動作できる構成とする。
- 常駐プロセス、root権限、外部計算APIを必要としない。
- 依存ライブラリは配布プラグインへ同梱し、本番サーバでのComposer実行を必須としない。

## 6. 機能の有効化

### 6.1 有効・無効設定

既存の「湘南オンライン」設定画面の「その他」タブへ「Welcart箱詰め設定」の利用チェックを追加する。有効時だけサイドメニューへ「箱詰め設定」を表示し、箱詰めロジックに関する設定をその画面へ集約する。利用チェック直後は設定準備状態とし、必須設定の検査に合格して基本設定を保存した後だけ箱詰め送料計算を常時有効とする。

### 6.2 無効時

無効時は次のすべてを満たすこと。

- 箱詰めライブラリを読み込まない。
- 新規の箱詰め計算、購入制御および送料差し替えに使うWelcartフックを登録しない。
- 外部決済遷移済みデータの受注ID連携、受注完全削除との連動、および期限切れ一時データの安全な清掃に必要な最小限のライフサイクル処理は継続する。
- サイドバーの「箱詰め送料」メニューは、設定確認、再開準備、過去受注、ログおよび外部決済の連携状態を確認できるよう表示を維持し、停止中バッジを表示する。
- 新規カートの設定不足警告は表示しない。外部決済遷移済みデータの連携失敗、データ破損その他の既存データに関する重大警告は表示する。
- Welcart標準の送料計算へ影響を与えない。

### 6.3 有効時

- 既存プラグインのサイドメニュー配下へ「箱詰め送料」を表示する。
- 箱詰め送料のPHP処理と必要なフックを登録する。
- 管理画面用の資産は対象画面でのみ読み込む。
- Welcartが無効または必要な連携機能が利用できない場合でもFatal errorを発生させず、管理者へ警告して箱詰め対象商品の購入を停止する。

### 6.4 有効化前の事前検査

「Welcart箱詰め設定」を利用する場合は、設定保存時に配送が必要な全商品・SKUを検査する。

- 箱詰め対象の商品数とSKU数を表示する。
- 寸法、必要な重量、梱包マージン、収納可能な有効外箱、配送方法、送料の不足件数と対象へのリンクを表示する。
- 設定不足がある場合はエラーとして設定保存を拒否する。確認操作による強行保存は提供しない。
- 有効化後は設定が完全なSKUだけ購入可能とし、不完全なSKUは本機能の販売可否判定で購入不可とする。Welcartの実在庫数および在庫状態は書き換えない。
- 不足設定を修正したSKUは再検証後に自動的に購入可能へ戻す。
- 管理者の同意、検査日時、検査件数をプラグイン用設定テーブルへ保存する。

### 6.5 想定する導入・運用フロー

管理者は次の順序で導入する。

1. Welcartで利用する配送方法、地域別送料、送料無料条件および個別対応配送を設定する。
2. サイドメニューの「箱詰め設定」を開き、「基本設定」タブで数量上限、重量・クール・マージン・天地固定の利用有無を設定する。
3. 外箱マスターへ内寸、Welcart配送方法、送料、優先順位を登録し、内容を確認して有効化する。
4. 商品共通設定へクール便必須と天地固定を設定し、全箱詰め対象SKUへ寸法、必要に応じて重量と梱包マージンを設定する。
5. 商品設定状況画面で不足、収納不能、無効な配送設定を解消し、参考計算で代表的な配送先とカートを確認する。
6. 有効化前検査の件数と影響を確認して、箱詰め送料計算を有効化する。
7. 有効化後は計算ログ、設定不足警告、受注の箱詰め結果および個別対応配送の注文を日常的に確認する。

購入から受注までの通常フローは次のとおりとする。

```text
カート投入
  → 配送先不要の必須設定・数量上限を検証
配送先／配送方法入力
  → 対象地域の送料・候補外箱・クール条件を検証
  → 重量／計算予算を事前判定
  → 箱詰め候補を生成して送料を決定
確認画面
  → 箱数・箱名・送料を表示し一時スナップショットを保存
注文確定または外部決済へ遷移
  → 入力の再検証または提示内容を凍結
受注作成
  → pre_order_idから受注IDを連携し正式スナップショットを保持
出荷運用
  → 通常は箱詰め結果を参照し、個別対応配送は管理者が発送方法を判断
```

設定不足または送料不足は購入停止とし、重量超過、計算予算超過および捕捉可能な計算例外は、適用可能な個別対応配送がある場合だけ注文全体を個別対応配送へ切り替える。管理者は購入停止をログと商品設定状況から修正し、個別対応配送は受注画面で理由を確認して実際の梱包・発送方法を決定する。

Welcart管理画面からの手動受注、決済直前ログから復旧した受注、定期購入等の拡張機能が自動生成した受注など、購入者の通常確認画面を通らない受注には、注文時の正式な箱詰め結果を推測して生成しない。受注作成経路を判定して「箱詰め未計算」または「箱詰め結果要確認」と表示し、管理者が現在の受注内容による初回参考計算を明示的に実行できるようにする。初回参考計算もWelcart受注の送料を自動変更せず、必要な変更は管理者がWelcart受注編集画面で確定する。

日常運用では「個別対応配送」タブと「システム状態」タブを確認する。個別対応配送は、担当設定、商品・温度帯・重量の確認、実発送方法の決定、購入者へ請求済み送料との差額確認、送料方針に応じて必要となる追加請求・返金の正規手順完了、Welcart受注への必要事項反映を行った後に対応済みとする。箱詰め機能の業務状態はWelcartの発送・入金状態を代替しないため、発送完了や決済完了はWelcartおよび決済事業者側でも別途確定する。

終業時は、当日作成された個別対応配送に担当者未設定がないこと、長期滞留が放置されていないこと、箱詰め結果要確認と外部決済要確認の残件、および重大エラーを確認する。担当交代時は管理画面上の最新状態を正とし、対応中レコードの担当者を明示的に引き継ぐ。

次の管理画面を提供する。機能停止中も設定確認、再開準備、過去データ閲覧および連携状態確認のため表示を維持し、新規の参考計算・参考再計算など実行を伴う機能だけを無効化する。

```text
湘南オンラインプラグイン
└ 箱詰め送料
   ├ 基本設定

   ├ 商品設定状況
   ├ 個別対応配送
   ├ 参考計算
   ├ 計算ログ
   └ システム状態
```

### 7.1 基本設定

- 重量判定を利用する
- クール必須判定を利用する
- 梱包マージンを利用する
- 天地固定を利用する
- 外箱選択基準の優先順
- 箱詰め対象SKU行数上限（20行固定）
- 箱詰め対象商品の同時購入数上限（初期値100点、設定可能範囲1～200点）
- 個別対応配送へ切り替える注文重量上限（初期値30,000g、設定可能範囲1～1,000,000g）
- 個別対応配送用のWelcart配送方法および送料
- 個別対応配送の送料方針（初期値「表示送料を確定額とする」、選択肢「表示送料を確定額とする」「注文後に差額確認を行う」）
- 確認画面の案内文（固定）
- ログ保存期間（1～365日の整数、初期値30日。不正値は保存を拒否）
- 個別対応配送および購入停止方針の表示

これらはサイドメニューの「箱詰め設定」にある「基本設定・運用」タブへ配置する。外箱マスター、商品設定状況、参考計算、計算ログも同じ画面の各タブへ配置する。

重量、クール、マージン、天地固定の各利用設定の初期値は無効とし、次のように扱う。

- 「Welcart箱詰め設定」が無効の場合、すべてのカートおよび受注未確定のチェックアウトに対する箱詰め計算、箱詰め機能固有の購入停止、送料差し替え、重量判定、クール必須判定、梱包マージンおよび天地固定を実行しない。保存済みデータは削除または初期化しない。
- ただし、機能停止前にクレジットカード等の外部決済事業者へ遷移済みで、凍結済みの一時スナップショットを持つ注文は例外とする。機能停止後に決済が成立しても凍結済み送料と箱詰め結果で受注を完了し、受注ID連携と復旧処理を継続する。機能停止を理由に成立済みまたは処理中の決済を失敗扱いにしない。決済がキャンセルまたは失敗して受注未作成のままカートへ戻った場合は、凍結を解除し、停止中のため箱詰め送料を適用せずWelcart標準計算へ戻す。
- 通常決済の確認画面へ箱詰め送料を表示した後、注文確定前に機能が停止された場合は、そのまま注文を確定せず「送料計算方法が変更されました。内容を再確認してください」と表示して配送入力画面または再生成した確認画面へ戻す。カート内容と入力済み配送先は保持し、Welcart標準送料で再計算した内容の再確認を必須とする。旧一時スナップショットは受注履歴として残さず、受注ID未連携の一時データとして通常の保持期限と清掃処理に従う。外部決済事業者へ遷移済みの場合だけ前項の凍結内容を維持する。
- Welcart標準送料の通常決済確認画面を表示した後、注文確定前に箱詰め機能が有効化された場合も、そのまま注文を確定させない。カートに箱詰め対象商品がある場合は、カート内容と入力済み配送先を保持したまま現在設定で箱詰め計算を実行し、箱詰め送料を表示した確認画面での再確認を必須とする。必須設定不足等があれば購入を停止する。箱詰め対象商品がない場合はWelcart標準処理を継続する。箱詰め機能の有効化前に外部決済事業者へ遷移済みの場合は、遷移時に提示したWelcart標準送料を維持し、決済途中から箱詰め送料へ切り替えない。
- 「重量判定を利用する」が無効の場合、SKU重量を必須とせず、注文重量の計算、重量上限判定、重量超過を理由とする個別対応配送への自動切替を行わない。BoxPackerへは計算専用の商品重量0gと実質無制限の箱最大重量を渡し、重量が箱詰め結果へ影響しないようにする。Welcart SKUへ保存済みの重量値は変更しない。
- 「クール必須判定を利用する」が無効の場合、商品のクール便必須設定を要求せず、クール便商品を起点とした全商品のクール便用外箱への切替を行わない。Welcart標準の配送方法およびクール区分は変更しない。
- 「梱包マージンを利用する」が無効の場合、SKUの梱包マージン要否および値を要求せず、SKUの実寸をそのまま箱詰め計算へ渡す。
- 「天地固定を利用する」が無効の場合、商品に天地固定設定を表示・要求せず、すべての箱詰め対象商品を自由回転として扱う。
- 各機能を無効から有効へ変更する際は、必要なSKU設定、商品設定、Welcart配送方法・送料の不足を保存前に検証し、管理者へ警告する。

SKU行数上限は20行固定とする。配送先で利用できる有効な登録外箱は、件数上限を設けずすべて計算対象とする。

変更不可の総計算予算を2,000とする。計算予算は、箱詰め対象商品数量を `Q`、SKU行数を `L`、配送先で利用できる登録外箱数を `B` として、`Q × (B + 1) × (1 + ceil(L ÷ 20))` で算出する。`B + 1` は外箱種類ごとの候補に全箱種混合候補を加えた実行回数である。浮動小数点演算へ依存せず、整数の切上げ除算で計算する。算出値が2,000を超える場合はBoxPackerを実行しない。

説明タブでは、自動箱詰め可能な商品数量の運用目安を100点として表示する。表示値は目安であり、実際はカートのSKU行数と配送先で有効な外箱数から注文ごとに判定する。

商品設定状況画面と計算ログ画面には、計算予算超過による個別対応配送の直近30日件数と日別推移を表示する。件数が継続的に発生する場合は、登録外箱数、SKU行数、購入数量および総計算予算の関係を確認する運用案内を表示し、総計算予算の絶対値を管理画面から引き上げる操作は提供しない。

### 7.2 外箱設定

外箱を複数登録できること。利用者が入力する箱コードは設けず、内部IDを自動採番する。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 箱名 | 必須 | 前後の空白を除去した1～100文字。管理画面および確認画面に表示する名称 |
| 内寸の幅 | 必須 | mm単位の正の整数 |
| 内寸の奥行 | 必須 | mm単位の正の整数 |
| 内寸の高さ | 必須 | mm単位の正の整数 |
| Welcart配送方法 | 必須 | Welcartに登録済みの配送方法から選択 |
| Welcart送料 | 必須 | Welcartに登録済みの送料から選択 |
| 優先順位 | 必須 | 1～999の整数。数値が小さいほど高優先 |
| 使用状態 | 必須 | 有効または無効 |

箱詰め判定には内寸を使用する。送料は、外箱へ関連付けたWelcart送料のうち、配送先に該当する金額を使用する。

外箱マスターにはWelcart配送方法IDと送料IDを参照値として保存し、変更可能な名称を関連付けキーに使用しない。管理画面では保存したIDからWelcartの現在名称を取得して表示する。名称変更だけの場合は関連付けを維持し、IDに対応する設定が削除または無効化された場合は対象外箱を候補から除外して管理者へ警告する。同名の配送方法または送料が複数存在してもIDで区別する。注文時スナップショットには、計算に使用した配送方法ID、送料ID、当時の各名称および配送先へ適用した金額を保存し、その後の名称変更に影響されないようにする。

外箱の内寸は、幅、奥行、高さをそれぞれ1～10,000mmの整数に制限する。管理画面の入力時と保存時の両方で検証し、範囲外の値は保存せず、対象項目にエラーを表示する。既存データに範囲外の寸法が見つかった場合は管理者へ警告し、その外箱を修正されるまで箱詰め候補から除外する。

外寸の入力項目および保存カラムは設けない。BoxPackerが外寸相当の値を要求する箇所には内寸と同じ値を渡し、収納判定、箱選択、送料および空き容積の比較をすべて内寸基準で行う。外寸から容積重量または梱包後サイズを計算しない。

同じ「配送方法＋送料」を複数の外箱へ設定できる。同寸法であっても配送方法または送料が異なる外箱は別データとして登録できる。

外箱の優先順位は1を最優先とし、1～999の整数に制限する。同じ優先順位を複数の外箱へ設定できる。同順位の場合は外箱選択基準の他の比較値を順に適用し、それらも同じ場合は外箱内部IDの小さい順で決定する。未入力、0、負数、1,000以上または整数以外は保存できない。外箱を複製した場合は元の優先順位を引き継ぐ。

外箱名は前後の空白を除去した後に1～100文字とし、HTMLタグおよび制御文字を許可しない。現在登録されている外箱間では完全一致する同名を許可しないが、大文字・小文字および全角・半角を自動変換または同一視しない。入力時と保存時の両方で検証し、不正な場合は保存せず既存値を維持して対象項目にエラーを表示する。外箱名を後から変更または外箱を削除しても、過去の受注スナップショットには注文時の外箱名を保持する。

外箱マスターテーブルでは、表示用名称を `VARCHAR(100)`、完全一致判定用の名称キーをUTF-8のバイト列を保持する `VARBINARY(400)` として保存し、名称キーへ一意インデックスを設定する。名称変更時は表示用名称と名称キーを同じ保存処理で更新する。これにより、完全に同じ文字列だけを重複として拒否し、大文字・小文字または全角・半角が異なる名称は別名として扱う。移行時に完全一致する既存名称の重複が見つかった場合は外箱を自動削除または自動改名せず、対象内部IDを管理者へ提示し、解消されるまでスキーマ更新と箱詰め機能の有効化を完了しない。

外箱を複製する場合は、新しい内部IDを発行し、寸法、配送方法、送料および優先順位を引き継ぐ。クール区分は複製した配送方法のWelcart設定から自動判定し、本機能独自の値として複製または保存しない。名称は `元の箱名（コピー）` を初期値とし、完全一致する名称が既に存在する場合は `元の箱名（コピー2）`、`元の箱名（コピー3）` のように使用可能な最小の連番を付ける。100文字を超える場合は接尾辞を残して元名称部分を短縮する。複製直後は無効状態で保存し、管理者が内容を確認して明示的に有効化するまで箱詰め候補へ含めない。複製元の内部IDとの永続的な関連付けは持たず、過去の受注履歴にも影響させない。

### 7.3 外箱設定の整合性

- 商品またはSKUから外箱を直接参照する設定は設けない。
- 外箱の使用停止および削除を許可する。削除は管理権限、nonce、削除対象の再取得、および確認画面を必須とする物理削除とし、復元機能は提供しない。必要な場合は新しい外箱として再登録する。
- 外箱の使用停止、再開、更新、削除後は箱詰め設定リビジョンを更新し、旧計算結果を無効化する。非外部決済では確認画面表示後であっても注文確定前に変更を検出した場合は再計算して再確認を必須とする。外部決済事業者への遷移後または受注確定後のスナップショットは変更しない。
- 外箱削除時は、削除した外箱の内部ID、箱名、実行したWordPressユーザーID、実行日時を運用ログへ保存し、通常のログ保存期間に従って初期値30日で削除する。
- 使用停止または削除済みのWelcart設定を参照する外箱は箱詰め候補から除外する。
- Welcart側の配送方法または送料が削除された場合、管理画面で管理者へ警告する。
- 過去の受注表示は、注文時に保存したスナップショットを使用し、現在の外箱マスターに依存しない。
- 初期版は外箱の物理在庫数を管理しない。現場で箱が欠品または利用不能になった場合は、管理者が該当外箱を直ちに使用停止し、代替箱と送料を登録・検証してから再開する。使用停止前に確定した受注のスナップショットは変更しないため、未出荷受注で該当外箱を使用予定の件数と受注IDを使用停止確認画面および運用ダッシュボードへ表示し、現場が代替梱包と送料差額を個別に確認できるようにする。
- 外箱、配送方法または送料を変更する前に、現在確認画面にいる未確定注文への再確認発生、外部決済遷移済み受注への非反映、未出荷受注への非反映、および箱詰め可能SKU件数の増減をプレビュー表示する。変更後は代表配送先の参考計算が未実施であることを管理者へ警告し、参考計算の実施日時・実行者・結果を設定変更履歴へ関連付ける。

### 7.4 商品設定状況

Welcart商品を横断的に確認できる一覧を提供する。

- 商品名
- 商品コード
- SKU数
- 箱詰め対象・例外区分
- SKU寸法
- 収納可能な有効外箱の有無
- SKU設定の有無
- SKU設定の不足
- SKU重量
- 梱包マージンの要否
- 設定状態
- 商品編集画面へのリンク

設定状態には少なくとも次を含める。

- 箱詰め設定済み
- 寸法不足
- 収納可能な有効外箱なし
- 対応箱へ収納不能
- 無効な外箱を参照
- 購入不可
- 適用可能な送料なし
- 箱詰め対象外の理由

設定不足または連携異常がある間は、適切な管理権限を持つ利用者のWordPress管理画面上部へ警告を継続表示する。

- 設定不足の商品数とSKU数を表示する。
- 商品設定状況画面および対象の商品編集画面へのリンクを表示する。
- 商品編集画面では不足項目と購入不可の理由を具体的に表示する。
- すべての問題が解消した時点で警告を自動的に消す。
- 初期版では管理者向け警告や個別対応連絡のための新規メールを本プラグインから送信しない。ただし、購入者が注文条件を後から確認できるよう、Welcartが送信する標準の注文受付メールへ注文時の箱詰め・配送案内を追記する。

商品設定状況画面から、箱詰め対象SKUの関連キー、商品・SKUコード、現在の寸法、重量、梱包マージン要否・値、および検証状態をCSVでエクスポートできる。CSVインポートはWordPress管理者だけが実行でき、UTF-8（BOMは許容）、固定ヘッダー、1ファイル5MiB以下、データ行5,000行以下とする。空行は行数へ含めず、同じPost IDとSKU `meta_id` の組み合わせが複数行あるCSVは拒否する。更新対象は商品Post IDとWelcart SKU `meta_id` の組み合わせで照合し、商品名または変更可能なSKUコードだけでは更新しない。

CSVインポートは必ず全行の「CSVを事前チェック」を先に実行し、追加・更新・変更なし・警告・エラー件数と行番号別理由を表示する。エラーが1件でもある場合は1行も保存しない。管理者が事前チェック結果を確認し、同じファイルのSHA-256ハッシュ、同じ箱詰め設定リビジョン、nonceおよび生成から15分以内の確認トークンが一致した場合だけ一括保存する。保存は1バッチ100行以下とし、各バッチ内を可能な限りトランザクション化する。途中失敗時は処理済み行と未処理行を取込ジョブへ記録し、同じジョブを再開しても処理済み行を二重更新しない。結果CSVには行番号、照合キー、結果コードおよび安全なエラー概要だけを出力し、個人情報を含めない。CSV出力では表計算ソフトによる数式実行を防ぐため、`=`, `+`, `-`, `@` で始まる文字列セルを無害化する。

商品編集画面では、同一商品の複数SKUへ寸法・梱包マージン設定を一括入力する補助操作を提供できる。ただし保存前にSKUごとの最終値を表示し、個別SKU設定の意図しない上書きを防ぐ確認を必須とする。

### 7.5 計算ログ

計算ログ一覧は1ページ50件のページ送りとし、全件を一度に読み込まない。期間、理由コード、追跡用エラーID、および受注IDによる絞り込みと、SKUコードの部分一致検索を提供する。検索条件は入力値を検証・サニタイズし、SQL条件にはプレースホルダーを使用し、画面への再表示時は適切にエスケープする。

### 7.6 個別対応配送一覧

重量超過、計算予算超過または捕捉可能な計算例外により個別対応配送となった受注を横断表示する。業務状態は「未対応」「対応中」「対応済み」の3種類とし、初期値は「未対応」とする。一覧には受注ID、注文日時、切替理由、注文重量、クール便商品の有無、切替前の配送方法、購入者へ請求した送料、担当者および最終更新日時を表示し、Welcart受注編集画面へ移動できるようにする。

業務状態の変更はWelcartの受注状態を自動変更しない。対象受注を編集できる権限を持つ担当者が、担当者、実際に採用した発送方法、対応日時および最大1,000文字の運用メモを保存できる。運用メモには決済情報または不要な個人情報を記録しない旨を画面へ表示し、保存時に制御文字除去と長さ検証、表示時にエスケープを行う。送料差額、追加請求または返金は自動処理せず、管理者がWelcartと決済事業者の正規手順で処理し、その完了有無だけを業務記録へ残す。

「未対応」と「対応中」の合計件数を箱詰め送料メニューのバッジへ表示する。受注が削除された場合は対応レコードも同時削除する。機能停止中も一覧閲覧と既存受注の業務状態更新を許可し、停止を理由に出荷対応を妨げない。

### 7.7 システム状態

箱詰めDBスキーマバージョン、BoxPackerバージョン、Welcart連携フックの利用可否、最終Cron成功日時、次回予定日時、受注ID連携待ち件数、外部決済遷移済み未連携件数、孤立設定件数および直近の重大エラーを表示する。日次Cronが前回成功から24時間を超えて実行されていない場合は管理画面へ警告する。

WordPress管理者はnonceと権限確認を経て「保守処理を今すぐ実行」できる。手動実行はCronと同じ排他制御・冪等処理を使用し、1回の処理件数と実行時間に上限を設ける。残件がある場合は件数を表示し、次回Cronまたは再度の手動実行へ繰り越す。処理中の多重実行を許可せず、最終開始・成功・失敗日時と処理件数を保存する。

### 7.8 管理画面の運用確認

箱詰め送料メニューの先頭には基本設定を表示する。受注対応は「個別対応配送」、ログやCron等の確認は「システム状態」で行う。日次確認メモ機能および対応件数カードは設けない。

個別対応配送の経過時間は個別対応業務レコードの作成日時から計測する。注意は24時間、長期滞留は48時間に固定する。未対応・対応中の一覧は経過時間が長い順を初期表示し、注意・長期滞留を色だけに依存しない文字とアイコンで区別する。初期版ではメール通知を行わず、WordPress管理画面のメニューバッジ、管理者向け通知およびダッシュボードで通知する。

ダッシュボードには「本日の確認日時」と確認したWordPressユーザーを記録する確認ボタンを設ける。確認操作は未処理件数を消去または既読扱いにせず、日次確認を行った監査記録だけを残す。最終確認から24時間を超えた場合は管理者向け通知を表示する。担当者不在時にも未処理一覧を引き継げるよう、担当者未設定だけの絞り込みとCSV出力を提供する。出力内容は受注ID、状態、理由、経過時間、担当者、更新日時および管理画面URLに限定し、購入者の氏名、住所、電話番号、メールアドレスを含めない。

直近30日について、箱詰め対象受注数、通常箱詰め件数、個別対応件数と比率、理由別件数、購入停止件数、未対応の最大経過時間、対応完了までの中央値、および送料差額あり件数を日別に表示する。0件の日も欠落させず表示し、集計値から対象一覧へ移動できるようにする。これは業務改善用の集計であり、購入者情報、売上額、カード情報は保持しない。

### 7.9 個別対応の競合・変更履歴

個別対応業務レコードの更新には、画面表示時の更新日時またはリビジョン番号を使った楽観ロックを適用する。他の担当者が先に更新していた場合は後勝ちで上書きせず、最新内容と自分の入力内容の差を表示して再確認させる。「対応中」への変更時に担当者が未設定なら実行ユーザーを自動設定できるが、すでに別担当者が設定されている場合は明示的な引継ぎ操作なしに担当者を変更しない。

状態、担当者、実発送方法、対応日時、運用メモ、対応結果および送料差額対応確認の変更は、変更前後、変更日時、実行ユーザーIDおよび変更理由を追記型の監査履歴へ保存する。監査履歴は通常の30日ログ削除対象にせず、関連受注が完全削除された時点で受注スナップショットとともに削除する。運用メモを編集した場合も旧内容を監査履歴へ保持するが、決済情報や不要な個人情報を入力しない注意を継続表示する。

## 8. 商品・SKU設定

### 8.1 箱詰め対象の判定

「Welcart箱詰め設定」が有効な場合、配送が必要な通常商品はすべて箱詰め対象とする。商品またはSKUごとにWelcart標準送料へ切り替える設定は提供しない。

次の商品だけを明示的な箱詰め対象外とする。

- 送料個別課金商品
- 店頭受取商品
- サービス商品
- ダウンロード商品
- その他の配送不要商品

箱詰め対象商品の各SKUにはSKU固有の寸法設定を必須とし、商品共通の寸法を継承するだけの運用は行わない。既存の配送対象商品も機能有効化と同時に箱詰め対象となり、必須設定が不足するSKUは管理者へ警告して購入不可とする。

### 8.2 商品共通の箱詰め設定

箱詰め送料を使用する商品には次を設定する。

- 配置制約
- クール便必須（「クール必須判定を利用する」が有効な場合。はい／いいえ）
- 天地固定（「天地固定を利用する」が有効な場合。初期値は未チェック）

商品単位またはSKU単位で使用可能外箱を選択・制限する設定は提供しない。使用可能な外箱は、SKU寸法、配置制約、配送方法、クール区分、外箱の有効状態、および配送先向け送料から注文時に自動抽出する。

### 8.3 SKU必須設定

箱詰め送料を使用する商品の全SKUに、次を必須設定する。

- 幅、奥行、高さ（mm単位の正の整数）
- 重量（「重量判定を利用する」が有効な場合。g単位の1以上の整数）
- 梱包マージンの要否（「梱包マージンを利用する」が有効な場合）
- 梱包マージン「必要」の場合は、全方向へ確保する共通マージン値（mm単位の1以上の整数）

梱包マージンはSKUの1個ごとに各面へ設定値を確保する。幅、奥行、高さの各寸法へ「マージン値×2」を加算し、加算後の寸法を箱詰め計算へ渡す。「不要」のSKUには加算しない。

SKUの幅、奥行、高さは、それぞれ1～10,000mmの整数に制限する。梱包マージンは1～1,000mmの整数に制限し、マージン加算後の各辺も10,000mm以下でなければならない。商品編集画面の入力時と保存時の両方で検証し、範囲外の値は保存せず、対象SKU行にエラーを表示する。既存データがいずれかの範囲を外れる場合は管理者へ警告し、修正されるまでそのSKUを購入不可として扱う。

Welcart 2.11.34のSKUデータには既存の `weight` フィールドと公式の取得・更新APIがあるため、重量は本プラグイン専用テーブルへ重複保存せず、この既存フィールドを使用する。ただしWelcart標準の商品編集画面には重量入力欄がないため、Welcartが提供するSKUフォームおよび追加・更新値のフィルターを利用し、本プラグインからSKU重量入力欄を追加する。Welcart本体のファイルおよびテーブル構造は変更しない。

重量判定が有効な場合は重量単位をグラム（g）に統一し、SKU重量は1～1,000,000gの整数、注文重量と重量上限はg単位の整数として扱う。管理画面の入力欄には単位 `g` を明示し、未入力、小数、0、負数、数値以外または1,000,001g以上のSKU重量は保存できない。重量判定が無効な場合はSKU重量を未設定のまま許可し、BoxPackerへ渡す0gは計算上の中立値としてSKU重量へ保存しない。

重量判定を有効化した時点で、箱詰め対象SKUの重量が未設定または範囲外の場合は管理者へ警告し、修正されるまでそのSKUを購入不可として扱う。1個のSKU重量が現在の注文重量上限を超えていても、1,000,000g以下であればSKU設定自体は保存できる。そのSKUを含む注文は通常の注文重量判定により、注文全体を個別対応配送へ切り替える。

### 8.4 配置制約

初期版では、採用予定ライブラリがPHP 7.4で確実に扱える次の2種類を提供する。

- 自由回転：幅、奥行、高さの向きを入れ替えて配置できる。
- 天地固定：横倒しや逆さまを禁止し、底面上での回転だけを許可する。

初期値は自由回転とする。「天地固定を利用する」が有効な場合だけ商品編集画面へ「天地固定」チェックを表示し、チェックされた商品の全SKUを天地固定として扱う。チェックされていない商品は自由回転とする。

## 9. 商品公開時の検証

### 9.1 検証対象

「箱詰め送料を使用する」商品の公開または公開済み商品の更新時に、次を検証する。

- 3辺の寸法が正の整数で設定されている。
- 全SKUに寸法があり、梱包マージンが有効な場合はマージン要否および必要な値が設定されている。
- 重量判定が有効な場合、全SKUの重量設定が有効である。
- クール必須判定が有効な場合、商品のクール便必須設定が選択されている。
- 天地固定機能が有効な場合、商品の天地固定チェックが有効な値として保存されている。
- 使用可能な有効外箱が1件以上ある。
- 少なくとも1つの有効な外箱へ商品が収納できる。
- 収納可能な外箱に関連付けられたWelcart配送方法と送料が有効である。

### 9.2 検証失敗時と購入制御

- 商品の公開・更新自体は妨げず、不足または不整合の内容を管理者へ警告する。
- 必須のSKU設定、特に寸法が不足しているSKUは、Welcartの在庫切れと同等に購入不可として扱う。
- この購入不可制御は実在庫数を上書きせず、本機能による販売可否判定として実装する。
- 商品一覧、商品編集画面、商品設定状況画面へ購入不可の理由を表示する。
- 設定を修正した時点で再検証し、問題がなくなったSKUだけ購入可能へ戻す。
- 管理者による警告無視または強制購入許可は提供しない。

下書き保存時にも検証結果を表示する。ただし、購入制御が必要になるのは公開中の商品だけとする。

## 10. 外箱選択基準

配送先で利用可能なすべての有効外箱を、内寸容量、優先順位、内部IDの昇順で評価し、同一入力から常に同じ結果を得る。

BoxPackerは、全外箱種類を容量順に使用できる混合候補と、外箱種類ごとに同じ箱を必要数使用した候補を生成する。結果の決定基準は次の固定順とし、管理画面から変更できない。

1. 使用箱数が少ない。
2. 使用した箱の内寸総容量が小さい。
3. 送料合計が安い。
4. 外箱の優先順位合計が小さい。
5. 外箱の内部ID順。

異なる外箱種類を混在させる無制限な総当たりは行わない。1件も完成結果を生成できない場合は収納不能として購入を停止する。

## 11. 送料計算

### 11.1 使用するWelcartフック

主な送料差し替えには、Welcart 2.11.34で確認した次のフィルターフックを使用する。

```php
apply_filters(
    'usces_filter_getShippingCharge',
    $charge,
    $cart,
    $entry
);
```

Welcartの料金確定時には `usces_filter_set_cart_fees_shipping_charge` も呼ばれるため、実装時に呼び出し順を確認し、二重計算または二重加算を防止する。

確認画面への遷移前検証と一時スナップショット保存には `usces_filter_delivery_check` を使用する。非外部決済の注文ボタン押下時の最終一致確認には `usces_purchase_check` を使用する。JavaScriptの確認Ajaxだけに依存せず、いずれもPHP側で検証する。

受注作成後の一時スナップショットと受注IDの連携には、Welcart 2.11.34で受注保存後に呼ばれる `usces_action_reg_orderdata` を使用する。このフックは受注本体保存後に呼ばれるため、連携更新失敗を理由に購入者へ注文失敗を返さず、受注前の一時保存と事後の復旧処理を組み合わせる。

Welcart受注編集画面への箱詰め結果表示には `usces_action_order_edit_form_detail_bottom` を使用する。Welcart 2.11.34の受注削除はゴミ箱を経由せず復元不能な物理削除であるため、`usces_action_del_orderdata` と一括削除時の `usces_action_collective_order_delete_each` から同じ関連データ削除サービスを呼び出す。フックが重複して呼ばれても安全な冪等処理とする。

受注削除前の管理画面には、関連する正式スナップショット、参考再計算履歴および個別対応業務記録も同時に削除されることを表示する。クレジットカード等の外部決済受注では「Welcart受注を削除しても決済事業者側の決済は取消・返金されない」ことを強調し、決済事業者側の必要な処理とDBバックアップを確認するチェックを追加する。本機能は受注削除に連動して決済取消または返金を実行しない。

### 11.2 計算対象の外箱

- 購入者が選択したWelcart配送方法と一致する外箱だけを候補とする。
- 外箱に関連付けられたWelcart送料を使用する。
- SKU寸法、配置制約、配送方法、クール区分、外箱の有効状態、および配送先向け送料の条件を満たす外箱だけを候補とする。
- 無効な外箱、削除された配送方法または送料を参照する外箱は候補から除外する。
- クール便商品が含まれる場合は、クール便用として登録された外箱だけを候補とする。

### 11.3 計算手順

1. 機能が有効か確認する。
2. カート内の箱詰め対象商品の購入数量合計を検証し、管理者が設定した上限を超える場合は購入を停止する。
3. カート内商品のSKU必須設定と、配送先・配送方法に適用できる送料の有無を検証する。
4. 重量判定が有効な場合はSKU重量×数量を合算し、注文重量が設定上限を超える場合は注文全体を定形外へ切り替える。
5. 有効な配送方法と送料設定の存在を確認したうえで、現在の注文条件に対するWelcartの送料無料判定結果を取得し、Welcartが0円を適用する場合は請求送料を0円とする。
6. クール必須判定が有効な場合はクール便商品の有無を判定し、該当する外箱を抽出する。
7. 送料個別課金商品を通常の箱詰め対象から分離する。
8. 商品・SKUのマージン加算後寸法、数量、重量、配置制約と、自動抽出した対象外箱を箱詰め計算へ渡す。
9. 単一箱または複数箱の候補を評価する。
10. 管理者が設定した外箱選択基準により組み合わせを決定する。
11. 各箱へ関連付けられたWelcart送料から配送先に該当する金額を取得する。
12. 送料個別課金商品のWelcart送料を加算し、注文全体の送料として返す。

### 11.4 Welcart標準ルールとの優先関係

- Welcartの送料無料条件を優先して請求送料を0円とする。本機能では注文金額等の送料無料閾値を独自に再実装せず、現在の注文条件に対するWelcartの判定結果を使用する。ただし、実際の発送に必要な有効な配送方法と送料設定の存在確認は省略しない。
- 箱詰め成功時はWelcartの商品別送料を箱詰め送料へ置き換える。
- 送料個別課金商品は通常商品と同梱せず、商品1個につき1個口の別箱として扱い、Welcart標準の送料個別課金と同じく「適用送料×購入数量」で計算する。
- 店頭受取、サービス商品、配送不要商品は箱詰め対象外とする。
- 箱詰め対象外の商品だけの注文はWelcart標準送料を維持する。
- 箱詰め対象商品と送料個別課金商品が混在する場合は、箱詰め送料と商品別送料を合算する。
- 送料個別課金商品の適用送料はWelcart標準の優先関係に従う。選択配送方法に固定送料がある場合は固定送料を使用し、「送料を固定しない」場合は商品に設定された送料を使用する。
- 送料個別課金商品の数量分の別箱を箱詰め結果と受注スナップショットへ記録するが、3次元箱詰め計算には渡さない。

### 11.5 重量と個別対応配送

- 本節の処理は「重量判定を利用する」が有効な場合だけ実行する。
- 注文重量上限の初期値は30,000g、設定可能範囲は1～1,000,000gとし、整数だけを保存する。管理画面入力、保存処理および判定処理で同じ範囲を検証し、未入力、0、負数、小数、数値以外または1,000,001g以上は保存せず直前の有効値を維持する。管理画面にはg単位の入力値に加えて、`30,000g（30kg）` のようにkg換算値を参考表示するが、保存と判定は常にg単位で行う。
- 注文重量は、カート内の配送が必要な全SKUについて「SKU重量×数量」を合算して求める。通常の箱詰め対象商品、クール便必須商品、送料個別課金商品を含める。
- 店頭受取商品、サービス商品、ダウンロード商品、その他の配送不要商品は注文重量へ含めない。
- 重量の計算単位はgとし、途中でkg等への単位変換を行わない。
- 重量上限判定には購入商品のSKU重量だけを使用し、外箱、緩衝材、保冷剤その他の梱包資材重量は含めない。
- 重量判定は箱詰め計算前に行い、選択された外箱や箱数によって注文重量を変化させない。
- 注文重量が基本設定の上限を超えた場合は、通常商品、クール便商品、送料個別課金商品を含む注文全体を個別対応配送へ切り替え、理由を「重量超過（定形外）」として箱詰め計算を行わない。初期設定では30,001g以上が切替対象となる。
- 個別対応配送の料金は本プラグイン内へ金額を直接保持せず、管理者がWelcartへ専用の配送方法・送料として一律料金等を設定する。
- 重量超過時は、受注上のWelcart配送方法を専用の「個別対応配送」へ切り替え、その配送方法に関連付けた送料を適用する。元の配送方法名のまま料金だけを差し替えない。
- 個別対応配送は自動的な発送方法の確定を意味しない。注文確定後、管理者が商品の内容、重量、温度帯を確認して実際の発送方法を個別に決定する。
- クール便商品を含む場合も重量超過を優先して個別対応配送へ切り替え、冷蔵・冷凍を含む具体的な発送方法は管理者が個別に判断する。
- 個別対応配送となった理由、切替前の配送方法、クール便商品の有無、管理者による発送方法の個別判断が必要なことを受注情報へ保存し、管理者向けに明示する。
- 配送先に適用できる個別対応配送の送料がない場合は購入を停止する。
- 注文重量が上限と等しい場合は定形外へ切り替えず、上限を超えた場合だけ切り替える。
- 重量上限以下の注文では、BoxPackerへSKUの実重量を渡して箱ごとの商品重量合計を取得し、受注スナップショットへ保存する。ただし外箱ごとの最大重量は設定せず、外箱重量0g、箱最大重量 `PHP_INT_MAX` 相当として、重量を収納可否や外箱選択の制約には使用しない。
- 箱別重量上限がないため、BoxPacker 3.12.1の `setMaxBoxesToBalanceWeight(0)` を使用して重量再配分処理を無効化する。重量再配分によって箱構成を変更せず、不要な追加計算を行わない。

### 11.6 クール便

- 本節の処理は「クール必須判定を利用する」が有効な場合だけ実行する。
- 商品単位の「クール便必須」が「はい」の商品をクール便商品とする。商品内の全SKUへ同じ設定を適用する。
- 本機能では冷蔵と冷凍を区別しない。外箱に関連付けたWelcart配送方法のクール区分が「常温」以外であればクール便用外箱として扱う。
- クール便商品が1点でも含まれる場合は、Welcartの公開フィルター `usces_filter_get_available_delivery_method` を利用し、購入者へ提示する配送方法を、クール区分が「常温」以外で、有効なクール便用外箱と配送先向け送料が存在する方法から再構成する。カート内通常商品のWelcart商品設定に同じクール配送方法が含まれていないことだけを理由に候補から除外しない。
- クール便商品を含まない場合は、本機能を理由にWelcartが算出した利用可能配送方法を追加・削除・並べ替えしない。
- 利用可能なクール対応配送方法が1件の場合はWelcart標準動作に従って自動選択し、複数ある場合は購入者が選択する。
- 通常便を選択済みのカートへクール便商品が追加された場合など、保存済みの配送方法が現在の候補に含まれない場合はその選択を無効化し、利用可能なクール対応配送方法から再選択させる。
- 画面上の選択肢制御だけに依存せず、確認画面への遷移時に配送方法の有効性をサーバー側で再検証する。非外部決済の注文実行時にもカートと一時スナップショットの一致を検証する。通常便ID等の不正送信は受け付けない。
- カートにクール便商品が1点でも含まれる場合は、カート内の全箱詰め対象商品をクール便用外箱へ入れる。
- 通常便用外箱との分割は行わない。
- 全商品を収納できる有効なクール便用外箱または適用可能なクール便送料がない場合は購入を停止する。
- 送料個別課金商品は別箱の原則を優先する。ただし注文全体が個別対応配送になる場合は個別対応を優先し、実際の発送方法は管理者が判断する。

### 11.7 複数箱

1箱へ収まらない場合は、登録済みの候補外箱を使って複数箱へ分割する。

- 各箱に関連付けられたWelcart送料を取得する。
- 箱ごとの送料を合算する。
- 同じ外箱を複数使用する場合も箱数分を加算する。
- 異なる外箱を使用する場合は、それぞれの送料を加算する。

送料は浮動小数点数のまま計算または保存せず、通貨ごとの最小通貨単位へ変換した整数として計算・比較・合算し、通貨コードとともに受注スナップショットへ保存する。日本円（JPY）は1円を整数1として扱う。Welcartから小数を含む金額を取得した場合は、その通貨の小数桁数に従って文字列から厳密に整数へ変換し、二進浮動小数点演算へ依存しない。金額、通貨コード、または変換精度が不正で安全に変換できない送料は設定不備として扱い、購入を停止する。

検索用送料カラムは最小通貨単位の `BIGINT UNSIGNED`、通貨コードは英大文字3文字の `CHAR(3)` とする。0は有効な送料として許可し、負数、小数のままの値または3文字の英大文字でない通貨コードは無効とする。箱数または数量を掛ける前と、各送料を合計へ加算する前に、DBの `BIGINT UNSIGNED` と実行中PHPの整数で安全に扱える範囲の両方を検査する。いずれかの安全範囲を超える場合は計算を続けず購入を停止する。

JSONスナップショット内の金額はJSON数値へ変換せず、符号なし整数を表す10進文字列として通貨コードとともに保存する。読込時は文字列の桁、符号、先頭ゼロの正規形、通貨コードおよび安全範囲を再検証してから計算または表示に使用する。

1注文内で使用する外箱送料、送料個別課金商品の送料および個別対応配送の送料は、すべてWelcartが対象注文へ使用する通貨コードと一致しなければならない。異なる通貨が1件でも含まれる場合は合算または自動換算を行わず購入を停止し、競合した送料IDと通貨コードを管理者へ警告する。本機能は為替レートおよび通貨換算機能を持たない。受注スナップショットには注文通貨を1つ保存し、箱・個別課金等の各送料明細にも検証用の通貨コードを保存する。

本機能では送料へ独自の税率を適用せず、税込・税別の再判定、消費税計算、端数処理および帳票上の税表示はWelcartへ委ねる。Welcartから取得した送料額を変更せず、使用箱数および送料個別課金商品の数量に応じて合算し、合算後の送料をWelcartの注文計算へ返す。受注スナップショットには箱ごとの取得送料、箱数、送料合計に加えて、計算時点で送料の税処理に影響するWelcart税設定の識別可能な値を保存する。非外部決済では確認画面表示後に税設定が変わった場合も再計算して再確認を必須とする。外部決済事業者への遷移後または受注確定後は、凍結した送料と税設定の記録を維持する。

例：

```text
冷凍60サイズ箱 × 2
→ 冷凍60サイズ送料 × 2

冷凍60サイズ箱 × 1 ＋ 冷凍80サイズ箱 × 1
→ 冷凍60サイズ送料 ＋ 冷凍80サイズ送料
```

## 12. 購入停止と個別対応配送

次の場合は安全に送料を確定できないため、Welcart標準送料へ自動的に戻さず購入を停止する。

- 配送が必要な商品に対し、配送先・配送方法に適用できる送料設定が1件もない。送料無料条件が成立する注文もこの検証対象とする。
- 商品またはSKUの必須設定が不足している。
- 商品が有効な候補外箱へ収納できない。
- 選択された配送方法に対応する有効外箱がない。
- 外箱に関連付けたWelcart配送方法または送料が無効である。
- 適用する送料の金額または通貨情報が不正で、最小通貨単位の整数へ安全に変換できない。
- 注文内の送料通貨がWelcartの注文通貨と一致しない、または複数通貨が混在している。
- クール便商品を含む注文に有効なクール便用外箱または送料がない。
- 重量超過または箱詰め計算上限超過時に適用できる個別対応配送の配送方法・送料がない。
- 送料個別課金商品に適用できるWelcart送料がない。
- カート内の箱詰め対象商品の購入数量合計が管理者設定の上限を超える。

購入停止時は次のように扱う。

- SKU必須設定不足を商品ページ表示時に判定できる場合は、購入操作後まで待たず、そのSKUのカート投入操作を無効化してWelcartの購入不可表示に合わせる。購入者へは「現在この商品は購入できません」と表示し、「寸法未設定」「重量未設定」等の管理上の原因を表示しない。別SKUが正常なら商品全体を購入不可にせず、購入可能なSKUを選択できるようにする。
- カート投入時および数量変更時は、SKU必須設定、箱詰め対象数量上限など配送先を必要としない条件をサーバー側で検証する。配送先が未入力であること、または送料をまだ地域判定できないことだけを理由にカート投入を拒否しない。カート画面で送料を表示する箇所では、未確定時に「配送先入力後に計算」相当の案内を表示できる。
- 配送先・配送方法の確定時、および確認画面への遷移時に、対象国・都道府県等へ適用可能な送料を含む全条件をサーバー側で再検証する。配送先確定後に有効な送料がなければ確認画面へ進めず購入を停止する。カートセッションに保存済みの配送先がある場合も、保存値だけを信頼せず確認画面への遷移時に現在値で再検証する。
- 非外部決済では注文実行直前にも、現在の入力と確認画面で保存した一時スナップショットの一致を検証する。クレジットカードを含む外部決済では、決済事業者へ送信する前に配送先別送料の確定と一時スナップショット保存を必須とする。
- 購入者へは店舗内部の設定名、SKU `meta_id`、外箱内部ID、送料ID、例外内容を表示せず、「何ができないか」「対象商品」「購入者ができる解決操作」を平易な日本語で表示する。管理者向けの原因と購入者向け文言を分離する。
- エラーは一時的なポップアップだけにせず、問題がある商品または入力欄の近くと画面上部のエラー概要へ表示する。カート内容、数量、配送先、配送方法、会員入力、備考および適用可能なクーポン等を保持し、修正できる画面へ戻るリンクを必ず提示する。
- 数量上限超過時は「このご注文では、対象商品を合計○点まで同時に購入できます。数量を減らすか、注文を分けてください」のように、現在の上限、現在数量および解決方法を表示する。どの商品が数量集計の対象かを商品名で示すが、内部の箱詰め対象フラグ名は表示しない。
- 商品設定不足、収納不能、送料不足、連携不能等の店舗側事情は、購入者へ「現在、この商品を含むご注文の配送方法を確定できません。対象商品をカートから外すか、時間をおいて再度お試しください。解消しない場合は店舗へお問い合わせください」と案内する。対象商品名を表示し、購入者に寸法・重量・外箱・送料設定の修正を求めない。
- 配送先により送料を確定できない場合は、入力された国・都道府県を示したうえで配送先入力へ戻す。住所全文をエラー文やURLへ含めない。単なる未入力では購入不能と断定せず、必要項目を入力すると計算されることを案内する。
- 技術的な一時障害では「時間をおいて再度お試しください」と追跡用エラーIDを表示し、連打を促さない。決済事業者への遷移後または注文ボタン押下後に結果が不明な場合は、「注文履歴または注文完了メールを確認し、確認できない場合はエラーIDを添えて店舗へお問い合わせください」と表示し、同じ注文の即時再実行を促さない。
- 管理者向けログへ理由、対象商品、SKUを保存する。

送料設定の有無は計算結果の金額ではなく、Welcart送料マスター、国、配送先地域のキーが有効に存在するかで判定する。

- 有効な送料設定の金額が0円の場合は購入可能とする。
- Welcartの送料無料条件によって請求送料が0円になる場合も購入可能とする。
- 送料無料適用時も、外箱送料、送料個別課金商品および個別対応配送についてWelcartから取得した現在の適用額を使用し、本機能独自の例外条件または閾値を追加しない。
- クーポン、ポイント、会員値引きその他の割引がある場合は、それらがWelcartの注文計算へ反映された後にWelcartの送料無料判定結果を取得する。本機能は値引きの適用順序または送料無料判定に用いる注文金額を変更しない。割引内容、送料無料判定に使用された金額または注文合計が変わった場合は、キャッシュと受注未確定の一時スナップショットのフィンガープリントを不一致とし、確認画面への遷移時、通常決済の確定直前、および外部決済事業者への遷移前に再検証する。
- 受注スナップショットには送料無料判定に使用した最小通貨単位の金額、通貨コードおよび成立結果を保存する。クーポンコード、ポイント履歴、会員識別子等の個人情報または認証に利用できる値は重複保存しない。
- 送料レコード、対象国・地域の値、参照中の送料IDが存在しない場合は、計算上0円になっても購入を停止する。
- 削除済み送料IDまたは無効な配送方法を参照する場合は購入を停止する。

SKU設定、外箱、送料、収納可否の事前検証がすべて成功した後、BoxPackerまたは本機能の配置制約処理が捕捉可能な技術例外を返した場合は、Welcart標準送料へ戻さず注文全体を個別対応配送へ切り替える。理由は「箱詰め計算エラー」として受注情報と管理者向けログへ保存する。

次は箱詰め計算エラーへ含めず、設定不備または収納不能として購入を停止する。

- SKU寸法、必要な重量、梱包マージンなどの入力不足または不正値
- 条件に合う有効な候補外箱がない、または商品がどの候補外箱にも収納できない
- 配送方法、送料、個別対応配送の設定不足
- 計算開始前に商品、外箱、配送設定の変更を検出した場合

PHPのメモリ不足、最大実行時間超過、プロセス停止等のFatal errorは通常の例外処理では個別対応配送へ切り替えられないため、入力検証と実行前上限によって発生を予防する。Fatal errorを通常の切替手段として使用しない。

必要なWelcartの関数、API、送料フックを利用できない場合は、標準送料へ自動的に戻さず購入を停止する。

- 管理画面へ箱詰め機能を利用できない警告を常時表示する。
- 新しい箱詰め対象商品のカート投入と、既存カートの注文確定を停止する。
- 利用できない関数、API、フック、検出したWelcartバージョンを管理者向けログへ保存する。
- 必要な連携機能が再び利用可能になり、ほかの設定不備がなければ自動的に購入可能へ戻す。

## 13. 確認画面

### 13.1 価格と配送条件の表示

確認画面では、商品小計、値引き、送料、税および支払総額をWelcart標準表示と矛盾なく示し、本機能の箱数案内によって別の送料が追加されるように見せない。箱ごとの送料を購入者向けに重複表示せず、購入者が支払う送料合計を正として表示する。確認画面から注文確定までに送料または支払総額が変わった場合は、変更前後と変更理由を表示して再確認を必須とし、無言で注文確定しない。

外箱名は購入者へ表示される名称であることを外箱設定画面へ明記し、有効化前に確認画面プレビューを必須とする。倉庫内の棚番号、原価、仕入先、配送契約コードその他の内部情報を箱名へ入力しない注意を表示する。過去の受注スナップショットには当時の表示名を保持する。

クール必須判定が有効でクール便商品を含む場合は、確認画面の配送方法付近へ「このご注文はクール便対象商品を含みます」と表示する。冷蔵・冷凍の具体的な区分をWelcartから確定できる場合だけその区分を表示し、不明な場合に推測しない。購入者が通常便を選択していた状態からクール対応配送方法の再選択が必要になった場合は、変更理由を表示して配送方法選択画面へ戻す。

### 13.2 複数箱案内

箱詰め成功かつ2箱以上になる場合だけ、Welcartの内容確認画面へ次の形式で表示する。

主表示には配送情報テーブル内の `usces_filter_confirm_shipping_info` を使用し、配送方法の近くへ案内行を追加する。同一リクエスト内で主表示が実行されたことを記録し、主表示が呼ばれないカスタムテンプレートでは `usces_filter_confirm_page_notes` をフォールバックとして使用する。両方のフィルターが呼ばれる標準テンプレートでは二重表示しない。どちらの公開フィルターも呼ばない独自テンプレートは自動挿入の保証対象外とし、管理者へ互換性警告を表示する。

```text
このご注文は2箱での発送予定です。

・冷凍60サイズ箱 × 1
・冷凍80サイズ箱 × 1
```

- 購入者へ箱ごとの商品内訳は表示しない。
- 1箱の場合は案内を表示しない。
- 店頭受取、サービス商品、配送不要注文では表示しない。
- 個別対応配送または購入停止となった場合は複数箱案内を表示しない。
- 文言は管理画面で変更できるようにする。
- 同一のカート内容、配送先、配送方法、設定状態では、送料計算と表示内容が一致すること。
- 複数箱が別々に届く可能性がある場合は、「複数の荷物に分かれて届く場合があります」と表示する。配送日時が同じになると保証せず、実際の配送状況は店舗が発行する発送案内または配送事業者の追跡情報を確認するよう案内する。

### 13.3 個別対応配送の購入者向け説明と同意

個別対応配送となる注文では、配送方法名だけで意味を判断させず、確認画面の送料付近へ次の内容を常時表示する。

- 商品の重量、数量または組み合わせにより、店舗が注文後に梱包・配送方法を確認すること。
- 確認画面に表示された送料と支払総額。
- 送料差額が発生する可能性の有無。
- 差額が発生する場合は、店舗が購入者へ連絡し、購入者の同意と必要な決済手続が完了するまで発送しないこと。
- 増額へ同意できない場合は、追加料金なしで注文をキャンセルできること。
- クール便商品を含む場合は、温度帯を店舗が確認すること。

送料差額が発生し得る運用を有効にする場合は、個別対応配送の注文に限り、上記を確認したことを示す未選択のチェックボックスを注文確定前に必須とする。利用規約への包括同意だけで代替せず、チェック状態を一時スナップショットと受注スナップショットへ保存する。チェックがない場合は注文を確定せず説明位置へフォーカスを移す。チェック文言は管理者が変更できるが、差額の可能性、事前連絡、同意前に増額しないこと、キャンセル可能であることを削除できない固定説明として併記する。

差額が発生しない一律料金運用の場合は「表示された送料が確定送料です」と表示し、差額同意チェックを求めない。個別対応配送の基本設定には「表示送料を確定額とする」と「注文後に差額確認を行う」を設け、初期値は顧客負担が予測可能な「表示送料を確定額とする」とする。前者では実送料が高くても購入者へ追加請求せず、安くなった場合の返金方針は店舗規約に従う。設定変更は新規注文だけに適用し、外部決済遷移済みまたは受注確定済みの同意条件を変更しない。

### 13.4 注文完了後に残す案内

Welcartの注文完了画面、標準の注文受付メールおよび利用可能な会員購入履歴へ、注文時に確定した箱数案内、クール便対象表示、個別対応配送の説明、購入者へ請求した送料、差額同意の有無を同じ意味で表示する。新しいメールを別送するのではなくWelcart標準メールへ追記し、メールテンプレートが対応フックを呼ばない場合は管理者へ互換性警告を表示する。

個別対応配送では「店舗で配送方法を確認後、必要な場合は連絡します」と表示するが、確約できない連絡期限または発送日を自動表示しない。注文完了画面やメールに「追加料金が確定した」と誤認させる表現を使用せず、増額は購入者の個別同意前に確定・請求しない。注文番号と店舗の問い合わせ導線を表示し、内部の理由コード、重量、計算予算、エラー詳細は表示しない。

問い合わせ導線はWelcartまたはサイトで公開済みの問い合わせページを使用し、管理画面でURLを指定する場合はHTTPSの同一サイトURLを初期条件とする。未設定または無効なURLを表示せず、サイトに公開された店舗連絡先へフォールバックする。問い合わせURLへ注文番号、氏名、メールアドレス、エラーID等をクエリ文字列で自動付与しない。

### 13.5 操作性とアクセシビリティ

購入停止、再確認および個別対応同意はJavaScriptだけに依存せず、サーバー側検証と通常のHTML送信でも同じ結果にする。モーダルまたはポップアップを使用する場合も、閉じた後に消える唯一の案内にせず本文内へ同じ内容を残す。

エラー概要にはページ内リンクを設け、キーボード操作時は最初のエラーまたは個別対応説明へフォーカスを移す。状態は色だけで表現せず、見出し、本文、アイコンの代替テキストおよび `aria-describedby` 等で関連付ける。動的更新は適切なライブリージョンで通知し、同じ内容を重複して読み上げない。

PCとスマートフォンの両方で、送料、支払総額、複数箱案内、クール便表示、個別対応説明、同意チェック、エラーおよび戻る操作が注文ボタンより前に確認できるようにする。注文処理中は二重送信を抑止し、進行中であることを文字で表示するが、サーバー側の冪等性を省略しない。ブラウザの戻る、再読み込み、セッション期限切れ後も二重注文を避け、必要な場合は現在のカート状態から再確認させる。

## 14. 参考計算

実際の注文処理と同じPHPサービスを使用し、管理画面で送料を試算できるようにする。

### 14.1 入力

- 商品およびSKU
- 数量
- 配送先都道府県
- Welcart配送方法
- 必要に応じた外箱選択基準の一時指定

外箱と送料は登録済みのWelcart設定を基準にし、外箱を複数パターン登録して比較する。

### 14.2 出力

- 計算結果の成功または失敗
- 選択された外箱
- 使用箱数
- 箱ごとの商品、SKU、数量
- 箱ごとの送料
- 送料合計
- 空き容積または容積使用率
- 適用した外箱選択基準
- 選択理由
- 梱包できなかった商品
- 個別対応配送または購入停止の有無と理由
- 計算時間

参考計算結果は原則として永続保存しない。

## 15. 受注情報

注文確定時の箱詰め結果をWelcart受注IDへ関連付け、本プラグイン側へ保存する。

### 15.1 保存内容

- Welcart受注ID
- 計算日時
- 計算結果の状態
- 使用した配送方法
- 個別対応配送への切替前の配送方法
- 個別対応配送の要否と理由
- クール便商品の有無
- 外箱名と外箱内部ID
- 箱数
- 箱ごとの送料
- 送料合計
- 箱ごとの商品ID、SKU、数量
- 個別対応配送または購入停止の有無と理由
- 計算に使用した寸法、配置制約、送料などのスナップショット

### 15.2 管理者向け表示

Welcart受注編集画面へ本プラグインの表示領域を追加し、保存済みの箱詰め結果を閲覧できるようにする。WordPress管理者に加え、Welcartの対象受注を閲覧・編集できる権限を持つ担当者も閲覧可能とする。正式スナップショット、箱構成および送料は閲覧専用とし、編集機能は提供しない。後述の参考再計算は別履歴を生成する操作であり、正式スナップショットの編集には該当しない。

管理画面から作成された手動受注、決済直前ログから復旧された受注、および定期購入等で自動生成された受注について、対応する正式スナップショットがない場合は「箱詰め未計算」、対応候補はあるが自動照合できない場合は「箱詰め結果要確認」と表示する。`pre_order_id` が存在しないこと自体を技術エラーにしない。対象受注を編集できる担当者は「初回参考計算」を実行できるが、その結果を注文時の正式スナップショットとは表示しない。

決済直前ログからの復旧では、復元された `pre_order_id`、受注作成日時、決済方式、入力フィンガープリント等で一時スナップショットを照合する。1件へ一意に照合できた場合だけ受注IDを連携する。候補なしまたは複数候補の場合は自動選択せず「箱詰め結果要確認」とし、候補の最小限の識別情報を管理者へ表示する。照合不能でも成立済み決済またはWelcart受注を失敗・削除扱いにしない。

受注確定後に管理者がWelcart上の商品、SKU、数量、配送先、配送方法または送料を編集しても、注文時の箱詰めスナップショットを上書きせず履歴として保持する。現在の受注内容から生成したフィンガープリントが注文時スナップショットと異なる場合は、受注編集画面に「注文時の箱詰め結果と現在の受注内容が異なります」と警告する。変更を検出しても箱構成または送料を自動再計算・自動更新しない。

箱詰めまたは送料へ影響する受注編集を検出した場合は、運用ダッシュボードへ「受注編集後要確認」として追加する。Welcart上で発送済みと明示されていない受注では、個別対応業務が対応済みであっても未対応へ戻し、直前の対応済み状態と再開理由を監査履歴へ残す。発送済み受注は未対応へ自動的に戻さず「発送後編集要確認」として表示し、管理者が返品・交換・追加発送等の別運用を確認して、理由付きで確認済みにする。受注のキャンセルまたは発送不要がWelcart上で確定した場合は、自動削除せず、担当者が対応結果を「キャンセル／発送不要」として対応済みにできる。通常発送、キャンセル、発送不要のいずれも対応結果として明示し、単に状態だけを対応済みにすることはできない。

個別対応を対応済みにするには、担当者、対応結果、対応日時を必須とする。通常発送の場合は実発送方法、クール必須商品の温度帯確認、購入者へ請求済み送料との差額有無、および差額がある場合の対応状況も必須とする。「注文後に差額確認を行う」で追加請求・返金が未完了の場合は対応済みにできず、「対応中」のまま次の作業内容を運用メモへ記録する。「表示送料を確定額とする」では購入者への追加請求を禁止し、実送料との差を店舗負担差額として記録する。決済事業者の取引ID、カード番号その他の決済情報は保存しない。

送料方針が「注文後に差額確認を行う」で差額が増額となる場合は、管理者が購入者への説明と同意、Welcartまたは決済事業者の正規手順による入金確認を完了するまで発送準備完了としない。減額となる場合は返金または請求額修正の完了を確認する。差額なしの場合も「差額なし」を明示選択する。購入者への連絡本文や決済操作そのものは初期版の対象外とするが、連絡済み日時、同意確認日時、差額区分、処理完了日時および実行ユーザーを個別対応業務記録へ保存できるようにする。自由記述へ購入者の連絡先や決済識別子を転記しない。

対象受注を編集できる権限を持つ担当者は、受注編集画面から現在の受注内容を使った「参考再計算」を明示的に実行できる。参考再計算結果は注文時スナップショットと区別して、実行日時、実行したWordPressユーザーID、使用した設定リビジョンおよび入力フィンガープリントとともに保存・表示する。参考再計算を実行してもWelcart受注の送料、商品、数量、配送方法および注文時スナップショットを変更しない。実際の送料変更は管理者がWelcartの受注編集機能で確認して確定する。

「Welcart箱詰め設定」が無効な間は箱詰め設定メニューを表示しない。再度有効化した後は参考再計算を利用可能にする。

参考再計算履歴は成功・失敗を合わせて1受注につき最新10件まで保存する固定仕様とし、管理者向け設定項目は設けない。11件目を保存するときは、正式な注文時スナップショットを残したまま最も古い参考再計算結果だけを削除する。上限整理によって削除した参考再計算履歴の件数、対象受注IDおよび実行日時を運用ログへ保存する。

参考再計算が購入停止相当、個別対応配送相当または技術的な計算エラーになった場合も、実行したWordPressユーザーID、実行日時、入力フィンガープリント、結果区分、理由コードおよび追跡用エラーIDを参考再計算履歴へ保存する。技術例外はサニタイズして長さを制限した概要だけを保存し、購入者の氏名、住所全文、電話番号、メールアドレスまたは決済情報を重複保存しない。失敗時もWelcart受注、送料および正式スナップショットを変更しない。管理画面では各履歴を「成功」「購入停止相当」「個別対応配送相当」「計算エラー」に区別して表示する。

## 16. データ保存方針

Welcartのテーブルへカラムを追加せず、Welcartのテーブル構造へ依存しない。

| データ | 保存先の方針 |
| --- | --- |
| 機能の有効・無効 | 既存のプラグイン用設定テーブル |
| 箱詰め基本設定 | 既存のプラグイン用設定テーブル |
| 外箱マスター | 本プラグイン専用テーブル |
| 商品共通設定 | 本プラグイン専用テーブル |
| SKU設定 | 寸法・梱包マージン等は本プラグイン専用テーブル。重量はWelcart既存SKUの `weight` フィールド |
| 受注箱詰め結果 | 本プラグイン専用テーブルへ1受注1行で保存。検索項目は通常カラム、詳細は `LONGTEXT` のJSONスナップショット |
| 計算ログ | 本プラグイン専用テーブル |

具体的なテーブル名、全カラム定義、複合インデックス名および段階的なデータ移行SQLは、本要件の型・一意性・保存期間・削除規則を変更しない範囲で実装設計へ落とし込む。

箱詰め機能で新設する専用テーブルは次の5種類に限定する。実テーブル名はWordPressの `$wpdb->prefix` と既存プラグインの命名規則に従う。

1. 外箱マスターテーブル：外箱寸法、配送方法、送料、優先順位、有効状態を保持する。
2. 商品共通設定テーブル：商品Post IDを一意キーとし、クール便必須、天地固定等の商品単位設定を保持する。
3. SKU設定テーブル：商品Post IDとWelcart SKUの `meta_id` の組み合わせを一意キーとし、寸法、梱包マージン要否等を保持する。重量は保持しない。
4. 受注箱詰め結果テーブル：Welcart受注IDを一意キーとし、検索用項目とJSONスナップショットを保持する。
5. 運用・エラーログテーブル：追跡用エラーID、理由コード、関連受注ID、最小限の調査情報、作成日時、保存期限を保持する。

単純な機能フラグ、上限値、表示文、箱詰め設定リビジョン等は既存のプラグイン用設定テーブルへ保存し、新しい基本設定専用テーブルは追加しない。商品・SKUと外箱の関連付けテーブルも追加しない。

既存のプラグイン用設定テーブルは `param_name` に通常インデックスしかなく同名設定を複数行保存できるため、箱詰め機能の導入時に一意インデックスへ移行する。現行コードは読込時の `LIMIT 1` に順序指定がなく、保存時は最大ID行を更新するため、最大ID行が現在の実読込値と同じとは限らない。移行前にテーブル全体をバックアップし、`param_name` ごとの全重複行、現在の実読込値、最大ID行および値の一致・不一致を検査する。

同じ `param_name` の全 `param_value` が完全一致する場合だけ、最大ID行を残して他の重複行を自動整理できる。値が1件でも異なる場合は自動削除または自動選択せずスキーマ移行を停止し、対象キー、各IDおよび値の差異を管理者だけが閲覧できる移行画面へ表示する。管理者が保持する値を明示的に選択し、バックアップ完了を確認した後に限り整理を再開する。箱詰め以外の既存設定も検査対象であることを明示する。整理件数と対象キー数を個人情報を含めず管理者向け移行ログへ記録し、その後で `param_name` へ一意インデックスを追加する。移行のいずれかが失敗した場合はスキーマ更新を成功扱いにせず、箱詰め機能を有効化しない。

テーブル作成・更新はプラグイン有効化時だけに依存せず、保存済みの箱詰めDBスキーマバージョンを起動時に確認し、必要な場合だけWordPressの `dbDelta()` と明示的なデータ移行処理を実行する。同じバージョンの移行を再実行しても結果が変わらない冪等な処理とする。

WordPress環境によってストレージエンジンや運用方法が異なるため、データベースの外部キー制約には依存せず、削除連動と孤立データ検出は権限・nonceを確認したプラグイン処理で行う。検索、重複防止、保存期限削除に必要な一意インデックスおよび通常インデックスは各専用テーブルへ設定する。

専用テーブルの内部主キーは `BIGINT UNSIGNED AUTO_INCREMENT`、WordPressの商品Post ID、受注IDおよびユーザーIDは `BIGINT UNSIGNED` とする。Welcart SKUの `meta_id`、配送方法IDおよび送料IDも `BIGINT UNSIGNED` で参照値として保持する。寸法、梱包マージンおよび重量は `INT UNSIGNED`、数量は `SMALLINT UNSIGNED`、優先順位と各種件数上限は `SMALLINT UNSIGNED`、有効・無効等のフラグは `TINYINT UNSIGNED`、設定リビジョンと試行回数は `BIGINT UNSIGNED` を基本とする。

DB型が格納できる最大値を管理画面または計算処理で許可する上限とはみなさない。DBから読み込んだ値も信頼せず、本仕様で定めた寸法、重量、数量、優先順位その他の範囲をPHP側で再検証し、範囲外の値を箱詰め計算へ渡さない。

本機能がDBへ保存する作成日時、更新日時、有効期限、保存期限、連携試行日時などの日時はすべてUTCへ統一し、期限判定と定期削除もUTCで実行する。検索用日時カラムはUTCの `DATETIME` とし、JSONスナップショット内の日時はUTCを明示したISO 8601形式（例：`2026-08-25T03:00:00Z`）で保存する。管理画面へ表示するときだけWordPressに設定されたタイムゾーンへ変換する。WordPressのタイムゾーン設定が後から変更されても、保存済みUTC値および過去のスナップショットは書き換えない。

受注箱詰め結果テーブルは、受注確定前の一時スナップショット、受注ID連携済みスナップショット、手動・復旧・自動生成受注の箱詰め状態、および個別対応配送の業務状態を同じテーブルで管理する。Welcart標準の `pre_order_id` は通常チェックアウトで必須かつ一意とするが、`pre_order_id` を持たない手動・自動生成受注ではNULLを許可する。Welcart受注IDは一時保存時のみNULLを許可し、連携後は一意制約を適用する。同じ受注の確定処理が複数回呼ばれても重複行を作成しない。

受注ID、`pre_order_id`、受注生成経路、正式スナップショット有無、照合状態、連携状態、計算状態、送料合計、個別対応配送または購入停止の理由コード、注文時の個別対応送料方針、購入者同意有無・同意日時・同意文面リビジョン、個別対応業務状態、担当WordPressユーザーID、実発送方法、対応結果、送料差額区分・対応状態、連絡済み日時、追加差額の同意確認日時、差額処理完了日時、対応日時、運用メモ、業務リビジョン、作成日時、更新日時、最終連携試行日時および試行回数など、一覧・参照・復旧・削除に使用する値は独立したカラムとして保存する。個別対応の追記型監査履歴は同じ受注箱詰め結果行の履歴JSONへ保存し、専用テーブル数を増やさない。`pre_order_id` は内部照合だけに使用し、公開APIの認証または認可には使用しない。

二重クリック、再送信、または並行リクエストによって同じ `pre_order_id` の計算・保存が同時実行される場合は、一意制約を最終的な重複防止とし、トランザクションを利用できる環境ではトランザクション、利用できない場合を含めて更新前状態を条件に含む条件付き更新によって競合を検出する。同じ入力フィンガープリントの再処理は保存済みの一時スナップショットを再利用する。入力が異なる場合は受注未連携の一時スナップショットに限り安全に更新し、受注ID連携済みのスナップショットは上書きしない。条件付き更新の再試行は同一リクエスト内で最大3回とし、それでも競合を解消できない場合は決済へ進めず、確認画面の再読み込みを購入者へ案内する。通常の二重操作および競合は個別対応配送または箱詰め計算エラーとして記録せず、必要な場合だけ競合専用の理由コードで運用ログへ記録する。

箱種類、箱数、箱ごとのSKU・数量・配置、計算時寸法・重量・マージン、配送方法・送料、候補探索結果などの正式な注文時結果は、スキーマバージョンを含むJSONとして正式スナップショット専用の `LONGTEXT` カラムへ保存する。参考再計算履歴は、正式スナップショットと混在させず、別の `LONGTEXT` カラムへスキーマバージョン付きJSONとして保存する。MySQL固有の `JSON` 型には依存しない。参考再計算時は正式スナップショットのカラムを更新しない。

正式スナップショットJSONは、正規化した保存内容からSHA-256チェックサムを生成して独立カラムへ保存し、読込時にJSON形式、スキーマバージョンおよびチェックサムを検証する。チェックサムは意図しない破損検出に使用し、認証または改ざん防止の秘密値として扱わない。保存前にはJSONエンコード成功を検証する。正式スナップショットまたは参考再計算履歴の片方が破損していても受注自体を失敗扱いにせず、正常な側は表示可能とし、破損した側だけを非表示にして追跡用エラーIDとともに管理者へ警告する。破損データを自動上書きまたは自動削除しない。

確認画面への遷移時に `usces_filter_delivery_check` を使用し、Welcartが生成済みの `pre_order_id` を照合キーとしてJSON生成と受注ID未確定の一時スナップショット保存を完了する。計算または一時保存に失敗した場合はフィルターから安全なエラーメッセージを返し、受注・決済を開始せず配送入力画面へ戻す。確認画面へ表示した箱詰め結果と送料は一時スナップショットへ保存するが、非外部決済では注文確定直前の再検証が完了するまで確定済みとして凍結しない。外部決済では決済事業者への遷移時点、その他は受注確定時点で凍結する。

非外部決済の注文実行時は `usces_purchase_check` を使用し、現在のカート、配送先、配送方法、および提示送料のフィンガープリントが同じ `pre_order_id` の一時スナップショットと一致することを確認する。一致しない場合は決済・受注登録へ進めず、確認画面を再生成させる。外部決済では確認画面から決済事業者へ直接送信される経路があるため、確認画面生成時に一時保存済みであることを必須とし、決済後の設定変更だけを理由に提示済みの注文を失敗扱いにしない。

確認画面で提示した箱詰め結果と送料の有効期限は、一時スナップショット作成から24時間とする。一時スナップショットへUTCの作成日時と有効期限を保存する。非外部決済では24時間経過後の注文実行を停止し、現在の設定で確認画面と一時スナップショットを再生成させる。

外部決済では、決済事業者への送信後または決済成立後に24時間の期限超過が判明しても、受注・決済を失敗扱いにせず、確認画面で提示済みの送料と箱詰め結果を受注へ適用する。この場合は「提示送料期限超過（外部決済）」を理由コードとして受注スナップショットと管理者向けログへ保存し、管理者へ警告する。

クレジットカードを含む外部決済の決済通知、重複防止、および受注生成はWelcart標準処理へ委ね、本機能から決済事業者固有の通知を直接処理しない。外部決済の送信前に、Welcartが発行した `pre_order_id` に対応する一時スナップショットの保存を完了させる。決済がキャンセルまたは失敗して受注未作成のままカートへ戻った場合は、次の確認画面遷移時に現在のカート、設定、送料および税設定を再検証し、必要に応じて同じ `pre_order_id` の受注未連携スナップショットを更新して再確認を必須とする。クレジットカード決済を本機能の存在だけを理由に選択不可にしない。

機能停止後に外部決済から受注が成立した場合は、受注編集画面に「箱詰め機能停止後に外部決済が完了した注文」と表示する。運用ログには受注ID、`pre_order_id`、完了日時および専用理由コードだけを保存し、購入者の決済情報は保存しない。

Welcart受注作成後は `usces_action_reg_orderdata` で `pre_order_id` に対応する一時スナップショットへ受注IDを設定する。受注作成後の連携更新に失敗した場合は、受注や決済が成立している可能性があるため購入者へ注文失敗を表示せず、一時スナップショットを保持して管理者へ重大警告を表示する。受注画面には復旧するまで「箱詰め結果の連携待ち」と表示し、Welcart標準の `get_order_id_by_pre_order_id()` 相当の照合を用いた定期処理および管理画面表示時の再試行で受注IDとの連携を復旧する。再試行は冪等とし、成功後に警告を自動解除する。

受注ID未連携の一時スナップショットは、確認画面生成時のWelcart決済方式区分も保持する。通常決済または外部決済を開始していない一時スナップショットは作成から24時間保持する。外部決済事業者へ遷移済みの一時スナップショットは最低30日間保持し、30日経過だけを理由に自動削除しない。提示送料の有効期限は、保持期間にかかわらず24時間とする。

各保持期限経過後の清掃処理では、削除前に同じ `pre_order_id` を保持するWelcart受注を再検索し、受注が見つかった場合は削除せず受注ID連携を再試行する。通常決済または外部決済未開始で対応受注が存在しない場合だけ放棄されたチェックアウトデータとして削除する。

外部決済遷移済みデータは、対応受注に加えてWelcartの決済直前ログまたは利用可能な公式照合情報を確認する。受注復旧の可能性が残る、照合機能がない、または状態不明の場合は自動削除せず「外部決済要確認」としてシステム状態画面へ残す。管理者が決済事業者側で未成立・取消済みであることを確認して「キャンセル確認済み」に変更した場合、または受注へ正常連携できた場合に清掃可能とする。確認操作には権限、nonce、確認日時、実行ユーザーIDおよび運用メモを必須とする。

清掃はWordPress Cronの定期処理で行い、アクセス不足等で予定時刻に実行されなかった場合は次回実行時に期限超過分を処理する。システム状態画面でも最終実行状況と残件を監視する。

箱詰め機能の設定データはWordPress Options APIへ保存せず、プラグインが管理するテーブルへ保存する。単純な有効・無効、数値上限、選択値は既存のプラグイン用設定テーブルを使用し、外箱、SKU設定、受注結果、計算ログのように複数行・検索・履歴管理が必要なデータは用途別の専用テーブルを使用する。

本プラグインを無効化またはアンインストールしても、再有効化および再インストール後に復旧できるよう、箱詰め機能の設定、外箱、商品・SKU設定、受注箱詰め結果、スナップショット、計算ログを保持する。商品共通設定を含む本機能のデータは投稿メタやWordPress Options APIへ保存せず、プラグインが管理するテーブルへ保存する。これらのデータは、管理者が専用の完全消去操作を明示的に実行した場合だけ削除する。完全消去操作には管理権限とnonceを必須とし、通常の設定保存やプラグイン無効化からは実行しない。

完全消去操作は「湘南オンライン」設定画面の「箱詰め設定」タブ最下部へ、通常設定と区別した危険操作として配置する。削除対象と復元できない旨を表示し、確認チェックおよび確認文字列 `完全消去` の入力が両方揃った場合だけ実行可能にする。

外部決済事業者へ遷移済みで受注ID未連携かつ「キャンセル確認済み」でない一時スナップショットが1件でも存在する場合は、完全消去を実行できない。管理画面へ対象件数と最古・最新の遷移日時を表示し、決済完了による受注連携または決済事業者側を確認した管理者のキャンセル確定を待つ。外部決済処理中・状態不明データだけを強制削除する機能は提供しない。通常決済、未開始またはキャンセル確認済みの一時データだけが残る場合は対象件数を最終確認画面へ表示し、管理者が確認操作を完了した場合に限り完全消去できる。受注ID連携済みスナップショットは、削除対象として明示したうえで完全消去に含める。

完全消去では箱詰め用の5専用テーブルを削除し、既存のプラグイン用設定テーブルから箱詰め機能専用の設定行だけを削除する。既存設定テーブル自体と他機能の設定行は削除しない。Welcart既存SKUの `weight` フィールドは本プラグイン以外からも利用される可能性があるため、完全消去時も値を変更または削除しない。

本プラグイン専用のSKU設定は、商品Post IDとWelcart SKUの `meta_id` の組み合わせで関連付ける。変更可能なSKUコードを関連付けの主キーにせず、検索・表示・履歴確認用のスナップショットとして保存する。

- SKUコードを変更しても、同じ `meta_id` の寸法・梱包マージン等の設定を維持する。
- SKUを削除した場合は、対応する現在設定を本プラグイン専用テーブルから削除する。
- 商品をWordPressのゴミ箱へ移した段階では、商品共通設定と配下のSKU設定を保持する。ゴミ箱内の商品は箱詰め対象、購入可否チェックおよび機能有効化時の不足件数から除外する。
- ゴミ箱から商品を復元した場合は、保持していた商品共通設定とSKU設定を再利用し、現在の箱詰め要件に対して再検証する。
- 商品を完全削除した時点で、配下の現在SKU設定と商品共通設定を削除し、削除件数、商品Post ID、実行日時を運用ログへ保存する。過去の受注スナップショットは削除しない。
- SKUを複製する場合は、新しい `meta_id` に寸法・梱包マージン等を複製する。
- Welcartに存在しないSKUを参照する孤立設定を検出し、管理者へ警告する。孤立データ検査ではゴミ箱内の商品とそのSKU設定を削除対象として扱わない。
- 受注時のSKUコード、寸法、重量、マージン、箱詰め結果は受注スナップショットへ保存し、SKUまたは商品削除後も過去の受注情報を保持する。

## 17. Welcart非改変要件

### 17.1 データベース

- Welcartテーブルへカラムを追加しない。
- Welcartテーブルの構造を変更しない。
- Welcart内部テーブルへ独自SQLでデータを書き込まない。
- Welcart受注IDなどは、本プラグイン側で参照値として保持する。

### 17.2 PHP

- Welcartの公開フックと公開関数を優先して使用する。
- Welcartのプラグインファイルを変更しない。
- Welcartの内部ファイルを直接読み込まない。
- Welcart内部クラスを継承または置換しない。
- 必要な関数、クラス、フックの利用可否を実行時に確認する。
- Welcart更新後も連携不能時にFatal errorを発生させず、管理者へ警告して箱詰め対象商品の購入を停止する。

### 17.3 JavaScriptとCSS

- WelcartのJavaScriptおよびCSSを変更または上書きしない。
- 本プラグイン専用ファイルとして管理する。
- 対象の管理画面または確認画面だけで読み込む。
- 名前空間または既存規則に沿った接頭辞を使用する。
- DOM全体の常時監視に依存しない。
- JavaScriptが実行できなくても送料計算はPHPだけで完結する。
- JavaScriptは管理画面の入力支援、並べ替え、参考計算の操作補助に限定する。

## 18. 箱詰めライブラリ

初期候補は `dvdoug/boxpacker` 3.12.1とする。

選定理由：

- MITライセンスで無料利用できる。
- EC配送向けの3次元箱詰めと複数箱を扱える。
- PHP 7.4およびPHP 8系に対応する。
- 商品単位の自由回転と天地固定を扱える。
- 箱ごとの梱包結果を取得できる。

最新版4系はPHP 8.2以上を必要とし、既存プラグインの最低PHP 7.4要件に適合しないため初期版では採用しない。

ライブラリはバージョンを固定し、ライセンス表記と依存関係を配布物へ含める。本番配布ZIPには必要な依存ファイルを同梱する。

重量判定が無効な場合は、BoxPackerへ商品重量0g、外箱重量0g、箱最大重量 `PHP_INT_MAX` 相当を渡し、ライブラリの重量制約を実質的に無効化する。重量判定が有効な場合はSKU実重量を渡すが、外箱重量0g、箱最大重量 `PHP_INT_MAX` 相当とし、重量は注文全体の事前上限判定と箱ごとの商品重量表示だけに使用する。どちらの場合も `setMaxBoxesToBalanceWeight(0)` で重量再配分を無効化し、本機能の注文重量上限には外箱重量を含めない。

## 19. 性能・運用要件

- さくらのレンタルサーバ スタンダードの共用環境で過剰なCPUまたはメモリを消費しない。
- 全組み合わせの無制限探索を行わない。
- 同時購入数は3次元箱詰め計算へ渡す商品のSKU数量合計で判定する。上限の初期値は100点、設定可能範囲は1～200点とし、「箱詰め設定」タブで管理者が変更できるようにする。200点を絶対上限とし、画面入力、サーバー側の保存処理、カート判定のすべてで範囲を検証する。設定上限を超えた場合は購入を停止する。送料個別課金商品、店頭受取、サービス商品、配送不要商品など、箱詰め対象外商品の数量は合計へ含めない。
- SKU行数は20行固定とする。
- 配送先で利用可能な有効外箱は、登録件数にかかわらずすべて容量、優先順位、内部IDの昇順で評価する。全箱種を使用できる混合候補と、各外箱種類を必要数使用した候補を生成し、箱数、使用箱の総容量、送料、優先順位の順で決定する。
- BoxPackerの実行前にSKU行数と箱詰め対象数量を検証する。上限を超える場合はBoxPackerを実行せず、注文全体を個別対応配送へ切り替える。
- `商品数量 × (配送先で利用できる登録外箱数 + 1) × (1 + SKU行数÷20の切上げ)` が変更不可の総計算予算2,000を超える場合はBoxPackerを実行しない。予算は決定的な整数演算によって実行前に評価する。
- 箱詰め計算上限超過による個別対応配送では、切替理由、各件数、適用した上限、切替前の配送方法を受注情報と管理者向けログへ保存する。
- 「説明」タブには、箱詰めで使用する用語、基本設定、外箱設定、商品・SKU設定、CSV取込、および固定のSKU行数上限、注意時間、長期滞留時間、ログ保持日数、自動箱詰め数量目安、確認画面案内文を説明とともに表示する。
- 商品設定状況画面および計算ログ画面には、直近30日間に総計算予算超過で個別対応配送へ切り替わった受注件数と日別推移を表示する。運用件数が多い場合も変更不可の総計算予算を自動的に引き上げず、登録外箱数、SKU行数および購入上限の見直し材料として使用する。
- 個別対応配送用の有効なWelcart配送方法または送料がない場合は購入を停止する。
- 同一条件の重複計算を避けるため、同一PHPリクエスト内のメモリキャッシュと、同一購入者のWelcartカートセッション内キャッシュを使用する。サイト利用者間で共有する永続キャッシュ、WordPress Options API、およびTransient APIには箱詰め計算結果を保存しない。
- カートセッション内キャッシュの有効期限は生成から5分とする。有効期限内でも、カート内容、配送先の国・都道府県、配送方法、商品・SKU設定、外箱、送料、箱詰め基本設定、または箱詰めライブラリのバージョンが異なる場合は再利用しない。
- キャッシュキーには上記入力を正規化して生成したフィンガープリントと、プラグイン用設定テーブルへ保存する箱詰め設定リビジョンを含める。氏名、住所全文、電話番号、メールアドレス、決済情報はキャッシュキーおよびキャッシュ値へ含めない。
- 商品・SKU設定、外箱、箱詰め基本設定を変更した場合は、保存処理の成功後に箱詰め設定リビジョンを更新し、旧リビジョンのキャッシュを即時に無効化する。Welcart側の配送方法・送料変更は、現在値のフィンガープリントが変化することで無効化する。
- 確認画面への遷移時はキャッシュの存在だけを根拠にせず、カート内容、配送先、配送方法、各参照データの存在、および設定リビジョンを再検証する。すべて一致する有効期限内の結果だけを再利用し、一致しない場合は計算上限を再検証して再計算し、成功結果を `pre_order_id` に紐づく一時スナップショットとして保存する。凍結の開始点は外部決済事業者への遷移時または受注確定時とする。
- 正常なカート試算は永続ログへ保存せず、受注確定時の結果だけを保持する。
- 設定不備、購入停止、箱詰め計算エラー、個別対応配送の運用ログは初期値30日で保持し、保存期限を過ぎたログを日次処理で自動削除する。保存期間は1～365日の整数で設定可能とし、管理画面表示時、保存時、および削除処理の実行時に範囲を検証する。0、366以上、小数、数値以外などの不正値は自動補正せず、設定保存を拒否して直前の有効値を維持し、管理画面へ入力条件を含むエラーを表示する。
- 運用ログおよびエラーログには、購入者の氏名、住所全文、電話番号、メールアドレス、決済情報を保存しない。原因調査に必要な場合だけ、受注ID、配送先の国・都道府県コード、商品Post ID、SKUの `meta_id` とSKUコード、理由コード、および技術的なエラー情報を記録する。
- 受注に紐づく箱詰め結果とスナップショットは30日ログの対象外とし、受注履歴用データとして保持する。
- 受注箱詰め結果およびスナップショットは購入者情報を重複保存せず、Welcart受注IDによって対象受注を参照する。
- Welcart受注の単体削除または一括削除が成功した時点で、関連する正式スナップショット、参考再計算履歴、個別対応業務記録および検索用受注箱詰め結果も削除する。Welcart受注には本仕様上のゴミ箱・復元段階を想定しない。
- 箱詰め基本設定、外箱、商品共通設定、SKU設定およびWelcart配送参照の変更では、変更対象、変更前後の安全な差分、実行ユーザーID、実行日時および設定リビジョンを運用ログへ保存する。商品・SKU設定およびCSV一括取込では変更理由を引き続き必須とする。外箱の追加・更新・複製・削除では変更理由を求めず、操作種別を固定文言で記録する。
- 前項の重要設定変更履歴は通常の運用ログと区別して365日保持し、日次確認記録は90日保持する。各保持期限は初期版では変更不可とし、完全消去時は削除対象件数を明示して他の箱詰めデータとともに削除する。
- 担当WordPressユーザーが削除または権限喪失した場合も過去のユーザーIDと表示名スナップショットを監査履歴へ残し、未対応・対応中レコードは「担当者要再設定」としてダッシュボードへ表示する。削除済みユーザーへ新規レコードを割り当てず、管理者が有効な担当者へ引き継ぐ。
- 緊急停止時は「その他」の「Welcart箱詰め設定」を無効化する。無効化と同時に内部の実行準備フラグも解除し、再度利用する場合は必須設定の検査と基本設定の保存を必要とする。停止中も既存受注の連携・清掃処理およびWelcart受注管理配下の個別対応一覧は継続する。
- 本番更新またはDBスキーマ移行前にDBバックアップ、未処理件数、外部決済要確認件数、Cron最終成功、Welcart・PHP・WordPress互換性を確認する。更新後は、通常便、クール便、送料個別課金、個別対応配送、購入停止、外部決済の代表ケースおよび管理ダッシュボードをスモークテストし、結果と確認者をリリース記録へ残す。移行失敗時は新規箱詰め計算を有効化せず、既存データの閲覧と外部決済連携を可能な範囲で維持する。

PHPの実行時間切れを通常の打切り手段として使用せず、SKU行数、購入数量、および登録外箱数を含む総計算予算の実行前上限によって制御する。実装後の統合性能検証およびさくらのレンタルサーバ スタンダード上の測定結果が基準を満たさない場合は、総計算予算を2,000未満へ引き下げる。

## 20. セキュリティ要件

- 箱詰め基本設定、外箱マスター、商品・SKU設定状況、CSV入出力、運用・エラーログ、システム状態および手動メンテナンス実行へのアクセスはWordPress管理者に限定する。
- 運用ダッシュボードと個別対応配送一覧はWelcartの対象受注を閲覧・編集できる担当者も利用できるが、システム状態、設定不足の全件集計、設定変更履歴および手動メンテナンスはWordPress管理者だけに表示する。担当者向け集計、件数、CSVおよびリンクから権限外の受注の存在やIDを推測できないようにする。
- 受注に保存された箱詰め結果は、WordPress管理者またはWelcartの対象受注を閲覧・編集できる権限を持つ担当者に限り閲覧できる。
- 個別対応配送一覧の閲覧および対応状態、担当者、実発送方法、対応日時、運用メモの更新は、WordPress管理者またはWelcartの対象受注を閲覧・編集できる権限を持つ担当者に限る。担当者は権限のある受注だけを操作できるよう、一覧取得時と更新時の両方で対象受注の権限を再検証する。
- データの完全消去はWordPress管理者だけが実行できる。
- 権限は管理画面の表示時だけでなく、保存、削除、Ajax、その他の処理実行時にも検証する。ロール名を直接判定せず、WordPressおよびWelcartの該当権限を使用する。
- 設定の保存、削除、複製にはnonceと権限を確認する。
- 寸法、数量、優先順位、内部IDなどを型と範囲で検証する。
- 出力先に応じてHTML、属性、URL、JavaScript用のエスケープを行う。
- 直接SQLを使用する場合は `$wpdb->prepare()` を使用する。
- 管理画面の表示文字列はWordPressの国際化関数を使用する。
- ログへ購入者の不要な個人情報を保存しない。
- 購入者向け画面および通常の管理画面には、例外メッセージ、SQL、サーバー上のファイルパス、スタックトレースなどの内部情報を表示しない。安全な共通メッセージと追跡用エラーIDを表示し、エラーIDによって対象ログを参照できるようにする。
- 追跡用エラーIDは重複を検査したUUID v4形式、理由コードは最大64文字の機械判定用固定コードとする。技術的なエラー概要は最大1,000文字とし、原因特定に必要な最小限の例外クラス名および関数名は保存できるが、スタックトレース、SQL全文およびサーバー絶対パスは保存しない。
- 技術的なエラー情報をログまたは参考再計算履歴へ保存する前に、APIキー、認証トークン、Cookie、セッションID、決済情報、個人情報その他の秘密情報に該当する値を除去またはマスクする。マスキング後のUnicode文字数を基準に1,000文字を超える末尾を切り詰め、切り詰め済みフラグを保存する。ログを管理画面へ出力するときは保存値を信頼せず、表示先に応じて必ずエスケープする。
- 運用ログおよびエラーログは管理画面での閲覧専用とし、個別の編集、選択削除、および一括削除機能は提供しない。ログの削除は設定した保存期間を過ぎた際の日次処理、または確認を伴うデータ完全消去によってのみ行う。

## 21. 受入条件

### 21.1 有効・無効

- 無効時に箱詰めライブラリ、新規計算用送料フックおよび新規カート向け設定不足警告が読み込まれない。
- 無効時の送料がWelcart標準結果と一致する。
- 無効時も箱詰め送料メニューから設定、過去受注、ログおよび連携状態を確認でき、停止中であることが明示される。
- 有効時は箱詰め送料メニューから新規計算用の管理機能と参考再計算を利用できる。
- 既存の「湘南オンライン」設定画面の「その他」タブに「Welcart箱詰め設定」の利用チェックが表示され、有効時だけサイドメニューに「箱詰め設定」が表示される。
- 重量判定を個別に有効・無効にでき、無効時はSKU重量を必須とせず定形外切替を行わない。
- クール必須判定を個別に有効・無効にでき、無効時は商品にクール必須設定を要求せず、Welcart標準のクール区分へ干渉しない。
- 梱包マージンを個別に有効・無効にでき、無効時はSKUのマージン設定を要求せず実寸で箱詰めする。
- 天地固定を個別に有効・無効にでき、無効時または商品側が未チェックの場合は自由回転として扱う。
- 有効化前に全対象商品・SKUの設定状況と購入不可になる件数が表示され、管理者の明示確認後だけ有効化できる。
- 通常決済の確認中に機能の有効・無効が変わった場合は、変更後の送料で再確認しない限り注文を確定できない。
- 外部決済へ遷移済みの注文は、遷移後の機能停止または設定変更だけを理由に失敗せず、提示済み内容で受注へ連携される。
- 日次Cronが24時間を超えて成功していない場合、または外部決済要確認・孤立データ・重大エラーが残る場合は、システム状態画面と管理メニューバッジで管理者へ警告される。
- 管理者はCronと同じ排他制御・冪等性・処理上限を使ってメンテナンス処理を手動実行でき、実行結果を確認できる。

### 21.2 外箱

- 複数の外箱を登録できる。
- 外箱へWelcart配送方法と送料を設定できる。
- 外箱は内寸だけを保持し、外寸の入力・保存・計算を行わない。
- 外箱名、寸法および優先順位の範囲と重複規則が保存時に検証される。
- 複製した外箱は一意な名称かつ無効状態で作成される。
- 購入者が選択した配送方法と異なる外箱が候補にならない。
- 無効な外箱または削除済みWelcart設定を参照する外箱が候補にならない。

### 21.3 商品・SKU

- 箱詰め対象商品の全SKUに寸法を設定でき、梱包マージンまたは重量判定が有効な場合は対応するSKU設定もできる。
- 梱包マージンが有効かつ必要なSKUだけ、1個ごとに各寸法へ設定値の2倍が加算される。
- 商品・SKUへ外箱を手動指定せず、寸法、配送方法、クール区分、有効状態、および送料から候補外箱が自動抽出される。
- 送料個別課金、店頭受取、サービス、ダウンロード、配送不要商品では箱詰め寸法を要求しない。
- SKU必須設定が不足する場合は管理者に警告され、該当SKUを購入できない。
- 商品・SKU設定を固定ヘッダーのCSVで出力でき、Post IDとSKUの `meta_id` を照合キーとして一括取込できる。取込前に全行を検証する「CSVを事前チェック」を必須とし、1件でもエラーがあれば一切保存しない。
- CSVの確認後にファイル内容、設定リビジョンまたは対象SKUが変化した場合は取込を拒否し、同一商品の複数SKUへの設定補助もプレビューと上書き確認なしには保存しない。

### 21.4 送料

- 1箱の場合に対応する送料が適用される。
- 複数箱の場合に箱ごとの送料が合算される。
- 固定優先順が「箱数、使用箱の内寸総容量、送料合計、外箱優先順位、内部ID」になっている。
- 管理者が優先順を変更できない。
- Welcartの送料無料条件が優先される。
- 送料無料条件が成立しても有効な配送方法と送料設定がなければ購入できない。
- 重量上限または箱詰め計算の事前上限を超える場合は、注文全体にWelcartの個別対応配送と送料が適用される。
- クール便商品が含まれる場合は全箱詰め対象商品がクール便用外箱へ入る。
- 送料個別課金商品は別箱とし、その商品のWelcart送料が加算される。
- 送料個別課金商品を複数購入した場合は、1個につき1個口として適用送料が数量分加算される。
- 適用可能な送料がない場合は購入できない。
- 有効な0円送料または送料無料条件は購入可能とし、送料設定が存在しないため0円となった場合は購入できない。
- 捕捉可能な箱詰め計算エラー時は個別対応配送へ切り替え、Welcart連携不能時は購入を停止する。
- 二重加算が発生しない。
- 説明画面に固定の「自動箱詰め数量の目安」が表示され、実際の計算可否は総計算予算とカート内容によって変わることが明記される。

### 21.5 表示・記録

- 2箱以上の場合だけ確認画面に箱数と箱名が表示される。
- 個別対応配送または購入停止時に複数箱案内が表示されない。
- 箱詰め対象商品の同時購入数が管理者設定の上限を超える場合に案内を表示し、注文確定へ進めない。
- 注文確定時の箱詰め結果が受注IDに紐づいて保存される。
- 外箱や送料設定を後から変更しても、注文時のスナップショットを確認できる。
- 受注編集後も正式スナップショットは上書きされず、差異警告と最大10件の参考再計算履歴を確認できる。
- 参考再計算の成功・失敗は区別して記録され、Welcart受注送料を自動変更しない。
- 手動受注、自動生成受注および正式スナップショットへ一意に照合できない復旧受注は、通常チェックアウトの正式結果を捏造せず「箱詰め未計算」または「箱詰め結果要確認」と表示される。
- 決済直前ログから復旧した受注は一意に照合できる場合だけ既存結果へ連携され、照合不能または複数候補の場合も受注・決済データを削除せず確認対象として残る。
- 個別対応配送になった受注は個別対応配送一覧へ「未対応」で登録され、「対応中」「対応済み」へ更新できる。未対応・対応中件数は管理メニューバッジに表示され、箱詰め機能停止中も一覧と更新機能を使用できる。
- 個別対応の完了登録は発送方法の業務記録だけを更新し、Welcart送料、クレジットカード等の決済額、決済事業者側の取消・返金・追加請求を自動変更しない。
- Welcart受注の単体・一括削除前に関連データ削除と外部決済非連動の警告が表示され、削除成功後は関連する箱詰め結果、履歴および個別対応業務記録が削除される。
- 外部決済遷移済みで未連携かつキャンセル未確認のデータは、30日経過だけでは削除されず、完全消去も拒否される。
- 既存設定テーブルの重複値がすべて同一の場合だけ自動整理され、値が異なる場合は管理者が保持値を選択するまで移行と箱詰め機能の有効化が停止する。
- 運用ダッシュボードから未対応、長期滞留、未担当、受注編集後要確認、外部決済要確認、設定不足およびシステム異常の各一覧へ移動でき、日次確認者と確認日時を記録できる。
- 個別対応は必須項目と送料差額対応が完了するまで対応済みにできず、同時更新は楽観ロックで検出され、担当者変更には明示的な引継ぎが必要となる。
- 未発送の対応済み受注で商品、数量、配送先、配送方法または送料が変更された場合は未対応へ戻り、以前の対応内容と再開理由が監査履歴に残る。
- 発送済み受注の編集は未対応へ自動的に戻らず「発送後編集要確認」となり、理由付きの確認操作までダッシュボードに残る。
- 「注文後に差額確認を行う」で送料差額がある個別対応は、購入者への連絡・同意と正規手順による追加請求または返金の完了を記録するまで対応済みにできない。「表示送料を確定額とする」では追加請求できず、どちらの方針でも差額なしを明示選択でき、決済情報は保存されない。
- 箱が欠品して外箱を使用停止した場合、以後の新規計算から除外される一方、停止前の未出荷受注は書き換えられず、影響受注一覧で代替梱包を確認できる。
- 機能停止および重要設定変更では操作種別、実行者、日時、変更前後および設定リビジョンが記録される。CSV一括取込ではこれらに加えて変更理由が記録される。

### 21.6 購入者体験

- 購入停止時に店舗内部の設定値や技術情報を表示せず、対象商品、購入できない内容、数量変更・商品削除・配送先修正・再試行・問い合わせのうち有効な解決方法が示される。
- 設定不足SKUは商品ページで購入不可となるが、同一商品の正常な別SKUは購入でき、購入者へ管理上の不足項目は表示されない。
- エラー後もカート、配送先その他の入力内容が保持され、ポップアップを閉じても本文内で原因と戻り先を確認できる。
- 確認画面の送料と支払総額が注文確定額と一致し、変化した場合は変更前後を示して購入者の再確認なしに確定されない。
- 複数箱では別々に届く可能性、クール便ではクール対象であることが注文前に分かり、1箱、配送不要、購入停止では不要な箱数案内が表示されない。
- 個別対応配送の送料方針の初期値が「表示送料を確定額とする」であり、この方針の受注へ注文後の追加請求を行えない。
- 「注文後に差額確認を行う」場合は、差額可能性、事前連絡、購入者同意前に増額しないこと、同意できない場合に追加料金なしでキャンセルできることが確認画面へ固定表示され、未選択の個別チェックなしに注文確定できない。
- 注文完了画面、Welcart標準注文受付メールおよび利用可能な会員購入履歴で、注文時の箱数、クール対象、個別対応条件、請求送料および差額同意を後から確認できる。
- 決済結果不明時に即時再注文を促さず、注文履歴、注文完了メール、注文番号および追跡用エラーIDによる確認方法が示される。
- JavaScript無効、キーボード操作、スクリーンリーダー、PCおよびスマートフォンでも、購入停止、再確認、個別対応同意および注文処理中の状態を認識・操作できる。
- 問い合わせ導線は有効な公開URLまたは店舗連絡先を使用し、URLへ注文番号、個人情報またはエラーIDを自動付与しない。

### 21.7 非改変と障害耐性

- Welcart本体のファイルおよびテーブルが変更されていない。
- 本機能のJavaScriptが動作しなくてもPHPの送料計算が動作する。
- Welcartが無効または連携不能でもFatal errorを発生させない。

## 23. 実装時の確認事項

顧客判断を要する仕様上の未決事項は残さない。次は仕様変更ではなく、実装および検証で適合性を確認する事項とする。確認結果が本仕様を満たさない場合は、黙って代替動作へ変更せず、影響と修正案を報告する。

1. Welcartで実際に使用する外部決済方式ごとの確認画面生成、一時スナップショット保存、決済成功・失敗・キャンセル後の復帰、決済直前ログからの復旧、受注ID連携、およびWelcart受注削除時に決済事業者側で必要となる取消・返金手順。
2. 本要件に基づく専用テーブルの全カラム、インデックス、既存設定値のバックアップと重複解決を含む冪等な移行処理、ロールバック不能時の停止方法、および完全消去処理。
3. Welcartの送料無料・値引き・税計算が実行されるフック順序と、本機能の送料差し替えおよび最終再検証の実行順序。
4. SWELLおよびTwenty Twenty-Fiveの確認画面テンプレートが標準フックを呼び出すことと、呼び出さないカスタムテンプレートでの管理者警告。
5. さくらのレンタルサーバ スタンダード相当環境で、総計算予算2,000が許容応答時間内に収まること。満たさない場合は絶対上限を上げず総計算予算を引き下げる。
6. 管理画面からの手動受注、実運用で使用する定期購入・自動受注機能、および決済直前ログ復旧の生成経路ごとに利用可能なWelcartフックと識別情報。
7. 本番環境でWordPress Cronが継続実行される構成、代替Cronの有無、実行間隔、同時実行防止、および管理者が障害通知を確認する運用担当者。
8. 本番投入前のSKU件数、商品数、既存設定テーブルの重複状況およびCSV一括設定に必要な最大ファイル規模を実データで測定し、本仕様の行数・ファイルサイズ・バッチ上限内に収まること。
